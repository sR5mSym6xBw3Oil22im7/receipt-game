2. コーディング規約

  • .editorconfig：UTF-8、改行LF、ファイル末尾に改行。
  • コードのコメントと画面の文言は日本語。
  • HTMLから読み込むCSS・スクリプトのURLには ?v= でバージョン文字列を付け、内容を変えたら更新する。
  • APIから受け取った文字列は textContent で表示する（innerHTML を使わない）。
  • 管理APIの呼び出しは adminFetch を使い、POST・DELETEにはCSRFトークン（X-XSRF-TOKEN）を付ける。
  • 画面の動きはCSSのtransition／animationのみ。prefers-reduced-motion で止まるようにする。
  • styles.css は変更せず、テーマは theme/base.css と theme/tNN.css で上書きする。
  • 新しいAPIを足すときは SecurityConfig の認可設定とREADMEのAPI表を更新する。

3. ローカル確認

cd reBack && mvn spring-boot:run -Dspring-boot.run.profiles=local
node reFront/server.mjs
cd reBack && mvn test
node --test reFront/test/smoke.test.mjs
node scripts/check_readme.mjs
node scripts/check_doc.mjs

4. 変更手順

  1. ブランチを切る（main 上で直接作業しない）。
  2. 変更し、テストを追加・更新する。
  3. 同期が必要なファイルを両方直す。
  4. mvn test とスモークテストを実行する。
  5. README・doc/ を直したら、node scripts/check_readme.mjs と node scripts/check_doc.mjs を実行する。
  6. コミット・プッシュはユーザーが依頼したときだけ行う。
  7. プッシュ後、GitHub Actions の ci が成功することを確認する。

同期が必要なファイル

  • reBack/src/main/resources/static/admin/ の app.js・select.js・login.js・admin-api.js ⇔ reFront/ の同名ファイル
  • reBack/src/main/resources/static/theme/ ⇔ reFront/theme/（元は reBack 側）
動画（reFront/video/ の mp4）のエンコードは、必ず1ファイルずつ順番に実行する。ffmpeg などを複数同時に走らせない。

5. レビュー観点

  • 認可：新しいエンドポイントが既定拒否の下で意図どおりか。
  • 入力：長さ・件数・範囲・型を検証しているか。
  • AI出力：検証してから使っているか。失敗時の代替があるか。
  • 秘密情報：コード・ログ・画面に出ていないか。
  • 同期ファイルの一致、?v= の更新。

6. 自動検査と自動ループ（GitHub Actions）

ci（自動検査）

.github/workflows/ci.yml が、main・sub01 へのpushとプルリクエストで、backend（mvn test）→ frontend（スモークテスト）→ readme → doc の順に直列で実行する。前のジョブが失敗したら後は実行しない。

auto-loop（自動レビューと自動修正）

  1. 同一リポジトリのプルリクエストに、ラベル auto-loop を付ける（forkのPRは対象外）。
  2. 検証（4つの検査）→ Claudeのレビュー（読み取り専用）→ 判定 → Claudeの修正 → 守衛（scripts/guard.sh）を、最大3周行う。その後、修正なしの最終確認を1回行う。
  3. 合格して修正があるときだけ、auto-fix/<PR番号> へpushし、元のPRのベースブランチ宛てに修正PRを作る。sub01・main へは自動でpushしない。
  4. 結果（clean / exhausted / ng / escalate / error）はPRにコメントされる。修正PRのマージは人が行う。

守衛（scripts/guard.sh）

判定内容
不合格（修正を破棄）既存テストの削除・書き換え（追加のみ可）、テストの無効化（@Disabled・.skip( など）、.github/・scripts/・.env の変更、合格テスト数の減少
人の確認（修正は保留）SecurityConfig.java・pom.xml・render.yml・Dockerfile の変更、差分500行超、README・doc/ の1ファイル50行超の削除、バイナリの変更

設定と制約

  • 認証は Secret CLAUDE_CODE_OAUTH_TOKEN（Pro契約の claude setup-token）。有効期間は1年で、2027年10月ごろに再発行する。APIキーは使わない。Gemini系のキーはActionsに置かない。
  • claude-code-action には github_token を明示して渡す。既定ブランチ main にワークフローがなくても動かすため。
  • リポジトリ設定「Allow GitHub Actions to create and approve pull requests」を有効にしてある。修正PRの自動作成に必要。
  • GITHUB_TOKEN によるpushと、自動ループが作ったPRでは ci.yml が自動起動しない。ループ内で同じ4検査を実行している。
  • .github/ と scripts/ は人が直す。直したら ci.yml と、sub01 宛ての試験用PR（マージしない）で確認する。
  • Claudeの利用枠はPro契約の枠で、手元の利用と共有する。PRを作るたびには動かさず、ラベルで手動起動する。
