1. ファイル責務

ファイル責務変更時の注意
reFront/index.html, index.jsメニューリンクの順番（対戦・デモ・管理者ログイン）と id はテストが検査する
reFront/config.js ⇔ static/admin/config.js接続先URLDEMO_URL・GAME_URL の2行以外は同じ内容にする（テストで検査）。サービス名を変えたら両方を直す
reFront/styles.css ⇔ static/admin/styles.css共通スタイルテーマ導入後は変更しない方針。変える場合は両方を同じ内容にする
static/theme/ ⇔ reFront/theme/日替わりテーマ元は reBack 側。コピーを同じ内容にする（テストで検査）
static/admin/*.js管理画面の処理バックエンドからだけ配信する。管理APIは adminFetch を使う
static/game/, static/demo/対戦とデモ計算を変えたら Java と engine.js の両方を直し、engine-parity.json を更新する
SecurityConfig.java認証・認可新しいAPIは明示的に許可しない限り拒否される。足したら README と API仕様書も更新する
application.yml設定値秘密情報に既定値を書かない
README.md, doc/説明・開発文書仕様を変えたら記載も更新する

2. コーディング規約

  • .editorconfig に従う：UTF-8、改行LF、ファイル末尾に改行。
  • コメントは日本語で、なぜそうしているかを書く。
  • HTMLから読み込むCSS・スクリプトのURLには ?v= を付け、内容を変えたら更新する（スモークテストが upload.html の app.js の版を検査）。
  • APIから受け取った文字列は textContent で表示する。HTMLを組み立てる場合（対戦画面）は必ずエスケープする。
  • 管理APIの呼び出しは admin-api.js の adminFetch を使い、POST・DELETE には X-XSRF-TOKEN を付ける。
  • 画面の動きはCSSのtransition／animationのみで、prefers-reduced-motion で止める。
  • テーマの見た目は theme/base.css と theme/tNN.css で上書きし、styles.css は変えない。
  • Java は record と final クラスを基本にし、DBの値はバインド変数で渡す。動的なテーブル名は必ず検証する。
  • 生成AIの出力は未検証の値として扱い、範囲・許可リストで正規化する。
  • 動画（reFront/video/ の mp4）のエンコードは1ファイルずつ順番に行い、複数を同時に実行しない。

3. ローカル確認

# DB（Docker の場合）。止まっていれば起動する
docker ps --filter name=receipt-game-db
docker restart receipt-game-db

# バックエンド（reBack/.env が必要）
cd reBack
mvn spring-boot:run -Dspring-boot.run.profiles=local

# フロントエンド（リポジトリ直下）
node reFront/server.mjs

# テスト
cd reBack && mvn test
node --test reFront/test/smoke.test.mjs
サービスを再起動・停止する前に、実際に何で動いているかを確認する（docker ps、ps、/proc/<pid>/cgroup）。このプロジェクトのDBはDockerコンテナ receipt-game-db で、ホストの postgresql.service とは関係ない。

4. 変更手順

  1. main から作業ブランチを切る。
  2. 変更し、関係するテストを追加・更新する。
  3. 同期が必要なファイル（config.js、styles.css、theme/、Java と engine.js）をそろえ、?v= を更新する。
  4. mvn test とスモークテストを実行する。
  5. README・doc/ の該当箇所を更新する。
  6. 差分に秘密情報がないことを確認してコミットする。

5. レビュー観点

観点確認すること
認可新しいAPIが SecurityConfig で意図どおりに許可・拒否されるか。対戦APIは席の確認をしているか
入力大きさ・件数・長さ・範囲に上限があるか。エラーが500にならないか
個人情報保存・表示・ログ・Gemini への送信に個人情報が含まれないか
生成AI失敗・上限・不正な出力のときに代わりの動きがあるか
表示APIの文字列を textContent／エスケープで扱っているか
同期同じ内容であるべきファイル、Java と JavaScript の計算がそろっているか
テスト変更に対応するテストがあるか
