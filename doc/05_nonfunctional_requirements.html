非機能要件一覧

分類ID要件判定基準
性能NFR-P01解析要求が無期限に待たない。Gemini呼び出しは180秒、画面の解析要求は210秒でタイムアウトする。
性能NFR-P02保存要求が無期限に待たない。画面の保存要求は30秒、SQLは20秒（spring.jdbc.template.query-timeout）でタイムアウトする。
性能NFR-P03解析中の経過が分かる。15秒ごとに経過秒数を表示する。
可用性NFR-A01バックエンドの稼働監視を可能にする。/api/healthが200と {"status":"UP"} を返す（render.ymlのhealthCheckPath）。
操作性NFR-U01処理の段階が分かる。解析画面に「画像を選ぶ・解析する・内容を確認・PostgreSQLへ保存」の段階表示を行う。
操作性NFR-U02二重送信を防ぐ。処理中は解析・保存ボタンを無効化する。
互換性NFR-C01スマートフォン幅でも操作できる。760px、560px以下でレイアウトを切り替える。
アクセシビリティNFR-X01状態の変化を支援技術へ伝える。状態表示欄に aria-live="polite" を設定する。prefers-reduced-motion 指定時はアニメーションを止める。
セキュリティNFR-S01秘密情報をソースへ固定記述しない。DB_PASSWORD、ADMIN_USERNAME、ADMIN_PASSWORD_HASH は既定値なしの環境変数とする。
セキュリティNFR-S02データ操作を管理者に限定する。/api/receipts 配下はROLE_ADMIN必須。宣言外の /api 配下は拒否する。
セキュリティNFR-S03更新要求をCSRFから守る。POST / DELETE に X-XSRF-TOKEN ヘッダーを要求する。
保守性NFR-M01責務ごとにコードを分割する。config / controller / service / repository / dto / exception に分ける。
保守性NFR-M02管理画面スクリプトの複製を一致させる。スモークテストで reFront/ と static/admin/ の同名ファイルを比較する。
文字コードNFR-E01日本語を正しく扱う。UTF-8で統一し、server.servlet.encoding.force を true とする。
データNFR-D01画像とAPIキーを保存しない。画像はSHA-256の算出とGeminiへの送信にだけ使う。APIキーは要求ごとに受け取る。

品質目標

  • バックエンドの自動テストとフロントエンドのスモークテストがすべて合格すること。
  • 認可について、未ログイン・管理者以外・CSRFなし・管理者の各条件をAPIごとに自動テストで確認すること。
  • APIから受け取った文字列を textContent で表示し、HTMLとして解釈しないこと。
