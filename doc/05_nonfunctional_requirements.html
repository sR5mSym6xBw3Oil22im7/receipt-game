非機能要件一覧

ID区分要件実現方法
NF-01セキュリティ管理APIは管理者だけが使える。/api/receipts 配下はHTTPメソッドを問わずROLE_ADMIN。未ログイン401、管理者以外403。
NF-02セキュリティ新しいAPIが意図せず公開されない。許可していない /api 配下は denyAll。
NF-03セキュリティCSRFを防ぐ。Cookie型のCSRFトークンを X-XSRF-TOKEN ヘッダーで送る（対戦APIはCookieを使わないため対象外）。
NF-04セキュリティパスワードの総当たりを遅らせる。5回失敗で15分ロック。照合中の要求も回数に含める。
NF-05セキュリティ対戦APIの乱用を防ぐ。IPごとにルーム作成5回／10分、参加10回／1分、画像カード10回／日。Geminiはキーごとに200回／日。
NF-06セキュリティ生成AIの出力を信用しない。数値は範囲に収め、名前はカタカナのみ、URL風の文字列は拒否。SVGは許可リストで検証。
NF-07プライバシー個人情報を保存・表示しない。保存前に検出して置換し、除去できなければ保存しない。画像は保存しない。
NF-08性能解析が長くても画面が固まらない。Gemini 180秒、画面210秒で打ち切り。15秒ごとに経過時間を表示する。
NF-09性能DBの処理が止まらない。JdbcTemplateのクエリタイムアウト20秒。
NF-10性能巨大な画像でメモリを使い切らない。5 MiB上限、約2,500万画素の上限（ヘッダーだけ読む）。回転は1,200万画素以下のときだけ。
NF-11可用性生成AIが使えなくても続けられる。用途別キー → 既定のキー → 計算式・代替イラスト（カード）／POWER最大（コンピュータ）。
NF-12可用性メモリ不足で中途半端に動き続けない。-XX:MaxRAMPercentage=70、-XX:+ExitOnOutOfMemoryError で終了させ、Renderに再起動させる。
NF-13整合性同じ画像を二重登録しない。receipt_image_hash_registry の主キーと、保存時の条件付きUPDATE。
NF-14整合性同じルームへの同時操作で状態が壊れない。トランザクション内で monster_room を SELECT … FOR UPDATE。
NF-15公正性勝敗を利用者が操作できない。サーバーで計算して保存し、画面は結果を再生するだけ。相手のカードは対戦開始まで返さない。
NF-16保守性画面のスクリプトの重複でずれが起きない。theme/ と config.js はテストで内容の一致を検査する。
NF-17アクセシビリティ動きが苦手な利用者に配慮する。動きはCSSのtransition／animationのみ。prefers-reduced-motion で止める。
NF-18運用設定を環境ごとに切り替えられる。環境変数と reBack/.env（OSの環境変数が優先）、local プロファイル。
