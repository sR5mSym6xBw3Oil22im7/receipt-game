1. 全体構成

プレイヤー / 管理者のブラウザーPC・スマートフォン
↓
GitHub Pages（reFront/）メニュー・動画・テーマ
Render Web Service（reBack/）Spring Boot：API＋/admin＋/game＋/demo
↓
Render PostgreSQLレシート・カード・ルーム
Google Gemini API画像解析・カード生成・CPU選択

ローカルでは reFront を node reFront/server.mjs（5051）、reBack を mvn spring-boot:run（8081）、DBをDockerコンテナ receipt-game-db（ホスト55432→5432）で動かす。

2. コンポーネント一覧

コンポーネント配置備考
静的フロントGitHub Pages（想定URL：https://sr5msym6xbw3oil22im7.github.io/receipt-game/reFront/index.html）reFront/config.js が localhost 以外で本番の接続先を使う
バックエンドRender（サービス名 receipt-game、Docker、rootDir: reBack）ヘルスチェック /api/health。サービス名を変えたら config.js も変更
DBRender PostgreSQL（receipt-analysis-psl-service、メジャー18、外部接続不可 ipAllowList: []）ローカル検証は postgres:16-alpine
AIGoogle Gemini APIキーは環境変数。画面入力・DB保存なし

3. 通信経路

経路プロトコル認証/保護
ブラウザー → GitHub PagesHTTPS—
ブラウザー → バックエンドHTTPS（Cookie Secure、SameSite=Lax）管理：セッション＋CSRF／対戦：席トークン
バックエンド → DBJDBC（Render内部接続）DBユーザー/パスワードは環境変数
バックエンド → GeminiHTTPSAPIキー（用途別）。タイムアウト180秒

4. 実行環境

項目値
JVMEclipse Temurin 21 JRE（Alpine）。-XX:MaxRAMPercentage=70 -XX:+ExitOnOutOfMemoryError
実行ユーザー非root（app）
ポートPORT（既定8081）
プロキシ背後server.forward-headers-strategy=framework、MONSTER_TRUST_FORWARDED_FOR=true（Render）

5. 構成上の制約

  • ログイン失敗・回数制限の記録はプロセスのメモリ内。複数インスタンス化すると共有されない。
  • ルーム・対戦状態はDBに保存するため、再起動後も続行できる（期限切れを除く）。
