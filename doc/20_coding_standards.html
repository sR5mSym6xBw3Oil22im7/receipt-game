1. 共通

項目規約
文字コード・改行UTF-8、改行LF、ファイル末尾に改行（.editorconfig）
言語コードのコメント・画面文言・ログ以外のメッセージは日本語。既存の書き方に合わせる
秘密情報APIキー、管理者パスワードハッシュ、DB接続情報をリポジトリに含めない。reBack/.env はGit管理外
外部入力APIから受け取った文字列は textContent で表示。innerHTML を使わない（対戦画面のカード描画のようにテンプレート文字列で組み立てる箇所は、必ず esc() でエスケープする）

2. Java（バックエンド）

  • Java 21、Spring Boot 4.1.0。パッケージは com.example.receipt。
  • レコード（record）でDTO/ビューを表現し、Bean Validationで入力を検査する。
  • 業務エラーは ReceiptException(HttpStatus, code, message)。例外の詳細をレスポンスに出さない。
  • SQLはパラメーターバインドを使う。動的なのは検証済みテーブル名（receipt_ + 32桁16進）のみ。
  • 外部API（Gemini）の呼出しはトランザクションの外で行い、行ロックを持たない。
  • 新しいAPIを足すときは SecurityConfig の認可設定とREADMEのAPI表（および 15）を更新する。
  • ログに秘密・個人情報・画像本文を出さない。

3. JavaScript / HTML / CSS（フロント）

  • ビルド不要の素のJavaScript。IIFE／"use strict" で即時実行。
  • 管理APIの呼出しは admin-api.js の adminFetch を使い、POST・DELETEにはCSRFトークン（X-XSRF-TOKEN）を付ける。
  • HTMLから読み込むCSS・スクリプトのURLには ?v= を付け、内容を変えたら更新する（スモークテストが upload.html の app.js のバージョンを検査）。
  • 画面の動きはCSSのtransition/animationのみ。prefers-reduced-motion で止まるようにする。
  • styles.css は変更しない。テーマは theme/base.css と theme/tNN.css で上書きする。
  • ブラウザー保存（sessionStorage）は try/catch で囲み、保存できなくても動く。

4. 同期が必要なファイル（片方だけ直さない）

正（元）複製検査
reBack/src/main/resources/static/admin/ の app.js・select.js・login.js・admin-api.jsreFront/ の同名ファイルテストが内容の一致を検査
reBack/src/main/resources/static/theme/reFront/theme/テストが内容の一致を検査

config.js は reFront と reBack/…/admin/ で、メニューURLなどの意図した差だけを許容して一致を検査する。

5. テスト

  • バックエンドはH2（インメモリ）を使うためPostgreSQL不要。Geminiは差し替えて実通信しない。
  • セキュリティ要件（認可・CSRF・入力検証）には統合テストを書く。
  • 対戦エンジンを変えたら MonsterEngineParityTest でデモ画面の engine.js との一致を保つ（engine-parity.json）。

6. 動画ファイルの扱い（作業規約）

  • 動画（reFront/video/ のmp4）のエンコードは必ず1ファイルずつ順番に実行する。ffmpegなどを複数同時に走らせない。
  • 前のファイルの処理が終わってから次を始める。
