レシート解析システム

レシート画像をGoogle Gemini APIで解析し、読み取った文字列を確認してからPostgreSQLへ保存するWebシステムです。Gemini APIを呼び出さずに画面の流れを確認できるデモもあります。

公開URL

  • フロントエンド：https://sr5msym6xbw3oil22im7.github.io/receipt-analysis/reFront/index.html
  • バックエンド：https://receipt-analysis-b8po.onrender.com
  • ヘルスチェック：https://receipt-analysis-b8po.onrender.com/api/health

主な機能

  • APIキー不要のデモ
  • 管理者ログインとログイン試行制限
  • JPEG / PNG画像、およびそれらをまとめたZIPのGemini解析
  • 解析結果のPostgreSQL保存と重複画像の拒否
  • 保存済みレシートの一覧・詳細・削除
  • ヘルスチェック

必要環境

  • Java 21
  • Maven
  • PostgreSQL
  • Node.js（フロントエンドのスモークテスト時）

ローカル起動

export DB_PASSWORD='（ローカルDBのパスワード）'
export ADMIN_USERNAME=admin
export ADMIN_PASSWORD_HASH='（BCrypt形式のハッシュ）'
cd reBack
mvn spring-boot:run -Dspring-boot.run.profiles=local

バックエンド：http://localhost:8081。起動後、reFront/index.html をブラウザーで開く。

テスト

cd reBack
mvn test

# リポジトリ直下で
node --test reFront/test/smoke.test.mjs

主要API

MethodPath概要
GET/api/health稼働確認
POST/api/auth/loginログイン
POST/api/auth/logoutログアウト
POST/api/receipts/analyze画像解析（管理者）
POST/api/receipts/save解析結果の保存（管理者）
GET/api/receipts一覧（管理者）
GET/api/receipts/{tableName}詳細（管理者）
DELETE/api/receipts/{tableName}削除（管理者）

注意事項

  • Gemini APIキーは解析のたびに画面で入力し、サーバーには保存しない。
  • 画像ファイルは保存しない。
  • 本番ではHTTPSを使い、SESSION_COOKIE_SECURE を有効にする（既定値 true）。
  • DBパスワード、管理者情報をリポジトリに含めない。
