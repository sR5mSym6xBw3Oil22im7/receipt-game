1. 提案の概要

レシート画像のAI解析とモンスター対戦を組み合わせたWebゲームを、フロントエンド（静的ページ）とバックエンド（Spring Boot）の2層構成で納品します。バックエンドはDockerで動作し、Renderへデプロイできる状態で提供します。

2. 提案範囲

区分内容成果物
ゲーム本体ルーム対戦、カード生成、CPU対戦、再戦、画像からのカード作成reBack/…/static/game/、…/monster/
管理機能ログイン、レシート解析・保存・一覧・詳細・削除reBack/…/static/admin/、/api/receipts
メニュー・演出メニューページ、日替わりテーマ、動画ページreFront/
デモ架空レシートによる体験版reBack/…/static/demo/
文書本書を含む開発文書、README 3点doc/、README.md、reBack/README.md、reFront/README.md

3. 技術方式

  • 言語・FW：Java 21 / Spring Boot 4.1.0 / Spring Security 7.1.0。
  • DB：PostgreSQL（Render本番、ローカルはDockerコンテナ receipt-game-db）。
  • AI：Google Gemini（モデル gemini-3.5-flash-lite、JSONスキーマ指定の構造化出力）。
  • フロント：ビルド不要の静的HTML/CSS/JavaScript（GitHub Pages想定）。
  • 選定理由と代替案の検討は 09 基本設計書 と 11 システム構成図 を参照。

4. 前提条件

  • Gemini APIキーは発注元（または運用者）が用意する。利用料・クォータはGoogleとの契約に従う。
  • Renderの無料プランを使う場合、無活動時の停止・起動待ち、DBの保持期間などはRenderの仕様に従う（本番想定プランは render.yml で plan: free）。
  • 対応するレシート画像はJPEG/PNG（最大5 MiB）。ZIPはJPEG/PNGのみのもの。
  • 管理者は1名（環境変数で設定）。複数管理者・権限管理は範囲外。

5. 体制・費用・納期

体制、見積金額、納期はソースから確認できません。07 体制図・03 見積前提書 の該当欄に 要記入 として用意しています。
