1. システム目的

レシート画像をGeminiで解析してPostgreSQLに保存し、保存済みレシートからモンスターカードを作って、ログインなしの2人対戦（または人対コンピュータ）を行えるようにする。保存するのは個人情報を取り除いた文字列と構造化データだけとし、画像そのものは保存しない。

2. 業務要件

ID要件
BR-01管理者は、レシート画像を解析して内容を確認し、確認後に保存する（解析だけではDBに登録しない）。
BR-02同じ画像のレシートを二重に登録しない。
BR-03保存するレシートから個人情報を取り除く。取り除けない場合は保存しない。
BR-04保存したレシートには、対戦で使うモンスターカードを1枚ずつ用意する。レシートを削除したらカードも削除する。
BR-05プレイヤーはログインせずに、ルームコードを共有して対戦できる。相手が来なければコンピュータと対戦する。
BR-06対戦の勝敗はサーバーで計算し、利用者が結果を操作できないようにする。
BR-07生成AIが使えないときも、計算式の値と代替イラストでゲームを続けられる。
BR-08見た目に変化をつけるため、画面のデザインを毎日切り替える。

3. 機能要件

3.1 共通・メニュー

  • メニューから、対戦画面・デモ画面・管理者ログイン・動画視聴ページ（操作ガイド標準版／簡易版、プロモーション映像1／2）へ移動できる。
  • 10種類のテーマが、日本時間の毎日3:00に順番に切り替わる。日付だけで決まり、どの端末でも同じ日は同じテーマになる。URLの ?theme=1〜10 で確認用に固定できる（保存しない）。
  • メニュー以外のページをアドレスバー・ブックマーク・外部サイトのリンクで直接開いた場合は、メニューへ移動する（管理画面 /admin/ を除く）。

3.2 管理者機能

  • ユーザーIDとパスワードでログインする。続けて5回失敗したユーザーIDは15分間ロックする（HTTP 429）。
  • JPEG / PNG画像（5 MiB以下、約2,500万画素以下）を解析し、行ごとの文字列と構造化データ（店舗名・支店名・店舗カテゴリー・購入日時・合計金額・支払方法・レシート番号・商品）を得る。
  • JPEG / PNGだけを含むZIPは、ブラウザーで展開して1枚ずつ解析する。
  • 解析結果を確認し、「データベースへ保存」で保存する。保存前に個人情報を「（非表示）」に置き換える。
  • 保存済みレシートを一覧表示し、行ごとの文字列を参照する。チェックしたレシートをまとめて削除する。

3.3 モンスターレシート対戦

  • ルームを作ると6桁のルームコードが発行される（作った人がP1）。コードを入力して参加した人がP2になる。
  • 待機時間（既定90秒）を過ぎてもP2が参加しなければ、コンピュータ対戦に切り替える。
  • 各プレイヤーに保存済みレシートを最大9枚配る。レシートをめくるとモンスターカードが現れ、手札になる（最大3枚）。有効なカードが10枚以上あれば、めくる前にシャッフル（配り直し）できる。
  • 自分のレシート画像から、その対戦で使うカードを1枚作れる（画像は保存しない。個人情報を取り除いて読み取る）。
  • 手札または画像のカードから1枚を決定する。両者が決定したら、サーバーが対戦を計算し、画面で再生する。相手のカードとレシートは対戦開始まで見えない。
  • 結果画面で、選ばれた2枚の元レシートを表示する。同じルームで再戦できる。どちらかが退出したらルームを閉じる。
  • コンピュータは配られたレシートから1〜3枚を手札にし、Geminiで1枚を選ぶ（使えなければPOWER最大）。

3.4 モンスターカード

  • 解析時に下書きを作り、保存時に有効にする。保存時は生成AIでパラメータとイラスト（SVG）を作り、失敗したら計算式の値と代替イラストを使う。
  • パラメータは属性（炎・土・風・雷・無）、レア度（N・R・SR・SSR）、HP・ATK・DEF・SPD・LUCK、必殺技と倍率、説明文。計算式はレシートの金額・品数・文字数・時刻・日付と画像ハッシュから決まる。
  • 起動時に、カードを持たない保存済みレシートを再点検してカードを作る。保存されなかった下書きは24時間で破棄する。

3.5 デモ

  • 架空のレシートでカード作成から対戦までを体験できる。Gemini API・対戦API・DBは使わない。相手プレイヤーとコンピュータはブラウザー内で自動操作する。

4. 非機能要件の概要

  • セキュリティ：管理APIはROLE_ADMINのみ、POST・DELETEはCSRFトークン必須。対戦APIは席トークンで認可し、回数制限をかける。CSPなどのセキュリティヘッダーを付ける。
  • 性能：Geminiの解析は最大180秒、画面側は210秒で打ち切る。対戦画面の状態確認は1〜2秒間隔。
  • 可用性：生成AIが使えなくても、解析以外の機能（保存・対戦）は続けられる。
  • 保守性：管理APIに新しいパスを足すときは明示的に許可する（既定で拒否）。
  • アクセシビリティ：画面の動きはCSSのみで、prefers-reduced-motion の環境では止める。

詳細は「非機能要件定義書」に示す。

5. 制約条件

  • Gemini APIキーはバックエンドの環境変数（GEMINI_API_DEFAULT 必須、用途別は任意）で設定し、画面からは入力しない。DBにも保存しない。
  • 管理者は環境変数（ADMIN_USERNAME、ADMIN_PASSWORD_HASH）で設定する1名とする。
  • Render・GitHub Pagesの無料枠の範囲で動かす。
  • 対戦には、有効なカードが2枚以上あることが望ましい（0枚でも画像から作ったカードやコンピュータの仮のカードで対戦できる）。
