1. システム目的

レシート画像をGemini APIで解析して文字列と構造化データを取り出し、管理者が内容を確認してからPostgreSQLへ保存し、保存済みデータを管理できるWebシステムを構築する。

2. 業務要件

ID要件優先度
BR-01レシート画像から印字された文字列を行単位で取り出せること。必須
BR-02解析結果を確認してから保存できること（解析だけではDBに登録しない）。必須
BR-03同じ画像を二重に登録できないこと。必須
BR-04解析・保存・閲覧・削除を管理者だけが行えること。必須
BR-05画像ファイルとGemini APIキーをサーバーに保存しないこと。必須
BR-06APIキーなしで操作の流れを確認できるデモがあること。必須

3. 機能要件

ID機能要件受入条件
FR-01メニューデモ、レシート解析、保存済みレシート確認への入口を表示する。
FR-02デモ「画像解析」押下後に固定データの解析結果を表示し、API・DBを呼び出さない。
FR-03ログイン正しいユーザーID・パスワードでログインでき、誤りの場合は401とする。
FR-04ログイン試行制限同じユーザーIDで連続5回失敗すると15分間429で拒否する。
FR-05レシート解析JPEG / PNG画像とGemini APIキーをPOST /api/receipts/analyzeへ送り、文字列・構造化データ・SHA-256を受け取って表示する。
FR-06ZIP一括解析JPEG / PNGだけを含むZIPをブラウザーで展開し、1枚ずつ解析する。
FR-07保存解析結果をPOST /api/receipts/saveで保存する。保存済みの画像は409とする。
FR-08一覧・詳細保存済みレシートの一覧（テーブル名・行数・作成日時）と、行番号付きの文字列を表示する。
FR-09削除選択したレシートを確認後に削除し、関連する構造化データと画像ハッシュも削除する。
FR-10ログアウトログアウト後は保存済みAPIを利用できない。
FR-11ヘルスチェックGET /api/healthで {"status":"UP"} を返す。

4. 非機能要件の概要

  • 解析・保存の要求は時間制限を設け、無期限に待たない。
  • 認可はバックエンドで行い、宣言していないAPIは拒否する。
  • 秘密情報（DBパスワード、管理者パスワードハッシュ）は環境変数で設定する。
  • スマートフォン幅でも操作できる。

詳細は非機能要件定義書に記載する。

5. 制約条件

  • 解析画像はJPEG / PNG、1ファイル5 MiBまで。
  • 管理者は1名。
  • Gemini APIキーは利用者が用意し、解析のたびに画面で入力する。
  • 管理画面はバックエンドから配信する。

6. 受入基準

  • バックエンドの自動テスト（mvn test）がすべて合格する。
  • フロントエンドのスモークテスト（node --test reFront/test/smoke.test.mjs）がすべて合格する。
  • 実際のレシート画像で、解析→保存→一覧→詳細→削除が行える。
  • 未ログインで管理画面を開くとログイン画面へリダイレクトされる。
  • デモがAPIキーなしで動作する。
