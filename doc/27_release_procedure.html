1. リリース前確認

No確認コマンド・方法

2. バックエンド公開

  1. 変更を main に取り込み、GitHub へ push する。
  2. Render が render.yml に従って Docker イメージをビルドし、デプロイする（自動デプロイを使わない場合はダッシュボードから Manual Deploy）。
  3. 初回、またはキーを足した場合は、sync: false の環境変数（ADMIN_USERNAME、ADMIN_PASSWORD_HASH、GEMINI_API_DEFAULT ほか）をダッシュボードで設定する。
  4. ヘルスチェック（/api/health）が通り、サービスが Live になるのを待つ。
  5. ログで起動エラーがないこと、カードの再点検の結果を確認する。

3. フロントエンド公開

  1. main に push すると GitHub Pages が reFront/ を含むリポジトリを公開する。
  2. https://sr5msym6xbw3oil22im7.github.io/receipt-game/reFront/index.html を開き、キャッシュに古いファイルが残っていないこと（?v= が新しいこと）を確認する。
  3. Render のサービス名を変えた場合は、reFront/config.js と admin/config.js、game/back-link.js、application.yml の app.frontend.menu-url の整合を確認する。

5. ロールバック

  • Render：ダッシュボードの Deploys から前のデプロイを選び、Rollback（再デプロイ）する。
  • GitHub Pages：問題のコミットを git revert して push する。
  • DB の変更（テーブル・列の追加）はアプリの起動時に行われるため、古い版に戻しても追加分は残る。古い版が追加分を使わないことを確認してから戻す。
