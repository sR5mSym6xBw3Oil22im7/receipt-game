34. 要確認事項・検討課題事項

1. リリース前確認

  1. cd reBack && mvn test と node --test reFront/test/smoke.test.mjs が全件成功する。
  2. 管理画面JS・テーマが reBack と reFront で一致している（テストで検査される）。
  3. HTMLから読み込むCSS・JSの ?v= を、内容を変えたものは更新した。
  4. reFront/config.js の接続先が Render のサービス名と一致している。
  5. Gemini APIキー、パスワードハッシュ、DB接続情報がコミットに含まれていない。

2. バックエンド公開

  1. Renderで reBack/render.yml のBlueprintを同期する。
  2. sync: false の環境変数（管理者、Geminiのキー）を設定する。
  3. デプロイ完了後、/api/health を確認する。

3. フロントエンド公開

  1. 変更をGitHubのデフォルトブランチへ反映する（コミット・プッシュは依頼があったときのみ行う）。
  2. GitHub Pagesの反映後、メニューを開いて確認する。

4. リリース判定チェック

項目確認
/api/healthUP
メニュー → 対戦／デモ／管理者ログイン表示できる
管理者ログイン成功する
デモでの対戦最後まで進む

5. ロールバック

第23章 6章のとおり。直前の正常なコミットを再デプロイする。
