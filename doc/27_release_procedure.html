1. リリース前確認

  1. 対象コミットを確認する。
  2. 秘密情報（DBパスワード、管理者情報、APIキー、.env）がリポジトリに含まれていないことを確認する。
  3. ADMIN_USERNAME と ADMIN_PASSWORD_HASH（BCrypt）を準備する。
  4. mvn test とスモークテストがすべて合格していることを確認する（テスト結果報告書）。
  5. reFront/config.js の公開用URLと、render.yml のサービス名が一致していることを確認する。

2. バックエンド公開

  1. Renderで reBack/render.yml を構成定義（Blueprint）として読み込み、Web Service と PostgreSQL を作成する。
  2. ADMIN_USERNAME と ADMIN_PASSWORD_HASH の値をRenderの画面で設定する（render.yml では sync: false）。
  3. DB接続の環境変数は render.yml の fromDatabase で設定される。
  4. デプロイを実行し、ビルド・起動ログを確認する。
  5. /api/health が 200 と {"status":"UP"} を返すことを確認する。

3. フロントエンド公開

  1. reFront/config.js の公開用バックエンドURLが https://receipt-analysis-b8po.onrender.com を指すことを確認する。
  2. GitHub Pages の配信対象ブランチへリリースコミットを反映する。
  3. 公開URL https://sr5msym6xbw3oil22im7.github.io/receipt-analysis/reFront/index.html へアクセスする。
  4. メニュー、デモ、ログイン、解析、一覧を確認する。

4. リリース判定チェック

確認項目判定

5. ロールバック

  1. 不具合を確認したら、直前の正常なコミットへ戻す変更を作成する。
  2. main へ反映し、Renderの再デプロイと GitHub Pages の更新を待つ。
  3. /api/health と主要画面を再確認する。
  4. DBのテーブルとデータはコードを戻しても残る。
