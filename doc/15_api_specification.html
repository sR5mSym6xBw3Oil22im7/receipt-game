上記以外の /api/** は管理者でも拒否する。席トークンは X-Seat-Token ヘッダー。新しいAPIを追加するときは SecurityConfig の認可設定とこの表を更新する。

2. POST /api/auth/login

リクエスト  {"username": "admin", "password": "（パスワード）"}
200  {"redirect": "/admin/menu.html"}
401  ユーザーIDまたはパスワードが正しくありません。
429  ログインの失敗が続いたため、しばらくしてから再度お試しください。

4. POST /api/receipts/save

リクエスト  {"lines": ["…"], "sha256": "（解析で返された値）", "structuredData": {…}}
200 OK       {"tableName": "receipt_（32桁16進）", "lineCount": 12, "lines": ["…"], "sha256": "…"}

入力制約は第11章 4章のとおり。同じ画像は409 DUPLICATE_RECEIPT_IMAGE。

5. GET /api/receipts、GET・DELETE /api/receipts/{tableName}

  • 一覧：[{"tableName", "lineCount", "createdAt"}]（テーブル名の降順）
  • 詳細：{tableName, lineCount, createdAt, lines:[{lineNo, text}]}
  • 削除：204。存在しない／不正な名前は404 RECEIPT_NOT_FOUND

6. 対戦API（/api/monster/rooms）

APIリクエスト主なレスポンス
作成／参加なしSeatResponse {code, seat, token, room}。tokenは作成・参加時のみ返る。
状態—RoomView {code, seat, status, mode, round, waitSecondsLeft, opponentJoined, opponentState, youConfirmed, battleReady, notice}
場—FieldView {round, receipts[], canShuffle, hand[], imageCard, selectedCardId, confirmed, handLimit}
flip{"index": 0〜8}めくったカードと更新後の場
image-cardmultipart file（JPEG/PNG ≤5 MiB）ImageCardResponse {card, reused, message, field}
select{"cardId": N}RoomView（双方決定で battleReady=true）
battle—BattleView {round, battleSeed, first, log[], winner, reason, finalHp, cards, receipts, mode}
rematch{"round": 現在のround}RoomView（roundが一致するときだけ配り直す）

カードの応答には、画像ハッシュ・テーブル名・行テキストを含めない。対戦APIの応答は Cache-Control: no-store。

対象上限超過時

ルーム参加（IP別）1分に10回429 RATE_LIMITED
