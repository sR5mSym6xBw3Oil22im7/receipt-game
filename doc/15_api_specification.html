1. API一覧

IDMethodPathRequestSuccessResponse用途
API-01GET/api/healthなし200{"status":"UP"}稼働監視
API-02GET/api/auth/csrfなし200{"token"}CSRFトークン取得
API-03GET/api/auth/sessionなし200{"authenticated"}ログイン状態確認
API-04POST/api/auth/loginLoginRequest200{"redirect"}ログイン
API-05POST/api/auth/logoutなし204なしログアウト
API-06POST/api/receipts/analyzemultipart200ReceiptText画像解析
API-07POST/api/receipts/saveReceiptSaveRequest200ReceiptUploadResponse解析結果の保存

API-10DELETE/api/receipts/{tableName}なし204なし削除

API-01～API-04は公開（API-04はCSRFトークン必須）。API-05はログイン済みかつCSRFトークン必須。API-06～API-10は管理者（ROLE_ADMIN）専用で、POST・DELETEはCSRFトークン（X-XSRF-TOKENヘッダー）が必要。API-06の multipart は file（画像）と geminiApiKey。

2. POST /api/auth/login

リクエスト

{"username": "admin", "password": "（パスワード）"}

成功レスポンス：200 OK

{"redirect": "/admin/select.html"}

失敗レスポンス

401: {"message": "ユーザーIDまたはパスワードが正しくありません。"}
429: {"message": "ログインの失敗が続いたため、しばらくしてから再度お試しください。"}

3. POST /api/receipts/analyze

リクエスト（multipart/form-data）

file         : レシート画像（image/jpeg または image/png）
geminiApiKey : Gemini APIキー

成功レスポンス：200 OK

{
  "lines": ["（読み取った1行目）", "（2行目）"],
  "sha256": "（画像のSHA-256。64桁の16進数）",
  "structuredData": {
    "storeName": "…", "branchName": null, "storeCategory": "…",
    "purchasedAt": "2026-09-15T12:34:00", "totalAmount": 1082,
    "paymentMethod": "…", "receiptNumber": null,
    "items": [{"name": "…", "category": "…", "quantity": 1, "unitPrice": 218, "amount": 218}]
  }
}

値は例。読み取れない項目は null になる。

4. POST /api/receipts/save

リクエスト

{"lines": ["…"], "sha256": "（解析で返された値）", "structuredData": {…}}

成功レスポンス：200 OK

{"tableName": "receipt_（32桁の16進数）", "lineCount": 12, "lines": ["…"], "sha256": "…"}

5. GET /api/receipts

成功レスポンス：200 OK

[
  {"tableName": "receipt_（32桁の16進数）", "lineCount": 12, "createdAt": "（作成日時）"}
]

並び順はテーブル名の降順。

6. GET /api/receipts/{tableName}

成功レスポンス：200 OK

{
  "tableName": "receipt_（32桁の16進数）", "lineCount": 12, "createdAt": "（作成日時）",
  "lines": [{"lineNo": 1, "text": "…"}, {"lineNo": 2, "text": "…"}]
}

7. DELETE /api/receipts/{tableName}

成功時は 204 No Content（本文なし）。存在しない場合は404 RECEIPT_NOT_FOUND。

8. エラーレスポンス

{
  "code": "DUPLICATE_RECEIPT_IMAGE",
  "message": "同じレシート画像は既にPostgreSQLへ登録されています。",
  "timestamp": "（発生日時）"
}
HTTP条件
400 Bad Request必須項目なし、空ファイル、APIキー未入力・形式不正、空のレシートデータ、不正な画像ハッシュ、Gemini APIによる要求拒否（4xx）。
401 Unauthorized未ログインでの管理者APIへのアクセス、ログイン失敗、GeminiがAPIキーを拒否。
403 Forbidden管理者以外のアクセス、CSRFトークンなし・不一致、宣言されていない /api パスへのログイン済みアクセス。
404 Not Found指定されたレシートがない、リソースがない。
405 Method Not Allowed対応していないHTTPメソッド。
409 Conflict保存済みの画像。
413 Payload Too Large画像が上限サイズを超える。
415 Unsupported Media TypeJPEG / PNG以外の画像。
422 Unprocessable ContentGeminiの応答が空、形式不正、文字なし。
429 Too Many Requestsログインのロック中、Gemini APIの利用上限。
500 Internal Server Error安全でないテーブル名、予期しないサーバー例外。
502 Bad GatewayGemini APIでの解析失敗（5xxなど）。
503 Service UnavailablePostgreSQLとの通信失敗。

Spring Securityが返す401・403は、上記のJSON形式（code・message）ではない。
