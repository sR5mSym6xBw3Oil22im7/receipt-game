1. ログイン入力チェック

チェックブラウザー（login.js）サーバー
必須ユーザーIDが空白のみ、またはパスワードが空なら「ユーザーIDとパスワードを入力してください。」@NotBlank（400 VALIDATION_ERROR）
桁数64文字／128文字を超えたら「ユーザーIDは64文字、パスワードは128文字以内で入力してください。」（入力欄にも maxlength）@Size(max=64)／@Size(max=128)
照合—BCryptで照合。失敗は401「ユーザーIDまたはパスワードが正しくありません。」
試行回数—ユーザーID（前後の空白を除き小文字にしてSHA-256）ごとに失敗＋照合中が5件に達したら429。最後の試行から15分で数え直す

2. 画像ファイルチェック

チェックブラウザー（app.js）サーバー（ReceiptUploadValidator・ImageInspector）
空「空のファイルです。画像を選択してください。」400 EMPTY_FILE
大きさ5 MiB超で「画像ファイルが大きすぎます（5 MiBまで）。」multipart上限 5MB（413 FILE_TOO_LARGE）、app.max-upload-bytes 5,242,880
Content-Type—image/jpeg、image/png 以外は 415 UNSUPPORTED_MEDIA_TYPE
中身先頭バイトがJPEG（FF D8 FF）／PNG（89 50 4E 47 0D 0A 1A 0A）でなければ中断同じ判定。違えば415
画素数—ヘッダーの幅×高さが25,000,000超で 413 IMAGE_TOO_LARGE（デコードしない）
重複—保存済みのSHA-256なら 409 DUPLICATE_RECEIPT_IMAGE（解析時・保存時）

対戦画面の画像カードも、サーバーで同じ中身・大きさ・画素数の検査を行う（MonsterRoomService.detectImageType）。ブラウザーでは file.type と5 MiBだけを確認する。

3. ZIPファイルチェック

チェック条件動作
判定拡張子 .zip、または type が application/zip・application/x-zip-compressedZIPとして展開する
大きさ50 MiB超中断
構造終端レコード・中央ディレクトリ・ローカルヘッダーが読めない／範囲外中断（「ZIPが壊れている可能性があります。」など）
件数51件以上中断（50件まで）
ディレクトリ名前が / で終わる、または属性がディレクトリ読み飛ばす
暗号化汎用フラグのbit0中断
種類拡張子が .jpg／.jpeg／.png 以外中断（1件でも混ざれば全体を中断）
1件の大きさ圧縮前・圧縮後のどちらかが5 MiB超、または展開中に5 MiBを超えた中断
合計展開後の合計が100 MiB超中断
圧縮方式0（無圧縮）・8（deflate）以外中断
中身展開後の長さが一致しない、またはJPEG/PNGの先頭バイトでない中断
0件画像が1件もない「ZIPファイルにレシート画像がありません。」

4. 保存データ・対戦APIのチェック

対象チェック結果
lines1,000行以下、1行500文字以下、NUL文字なし／空なら400 VALIDATION_ERROR／400 EMPTY_RECEIPT
sha25664桁の16進数400 VALIDATION_ERROR（INVALID_IMAGE_HASH）
structuredData名称255・カテゴリー50・支払方法100・レシート番号100文字以下、NULなし、金額 ±1,000,000,000、商品200件以下、数量は整数9桁・小数3桁以内400 VALIDATION_ERROR（項目名とメッセージだけ返し、値は返さない）
個人情報置換後にも検出規則に当たる422 PERSONAL_INFO_CHECK_FAILED
tableNamereceipt_ ＋ 32桁の小文字16進数形式違い・存在しないものは 404 RECEIPT_NOT_FOUND
ルームコード[A-HJ-NP-Z2-9]{6}（前後の空白を除いて大文字化）400 INVALID_ROOM_CODE
席トークンX-Seat-Token のSHA-256がP1またはP2と一致（定数時間比較）403 SEAT_REQUIRED（ルームがない場合も同じ）
flip の index0以上、配られた枚数未満400 INVALID_INDEX
select の cardId手札または画像カードのID400 CARD_NOT_IN_HAND
rematch の round現在のラウンド番号と一致するときだけ配り直す（違えば何もしない）対戦中でなければ 409 REMATCH_NOT_ALLOWED

5. Gemini APIキーチェック

  • 起動時：GEMINI_API_DEFAULT が空（前後の空白を除く）なら起動を中止する（IllegalStateException）。
  • 解析時：キーの前後の空白を除き、空なら503 GEMINI_API_KEY_MISSING、512文字を超えたら503 INVALID_GEMINI_API_KEY。
  • 用途別のキー（ANALYZE・MONSTER・PLAYER1・PLAYER2）が空なら GEMINI_API_DEFAULT を使う。画面ではキーを入力・送信しない。

6. エラー表示方式

画面方式
ログインlogin-status にメッセージ（HTTP 401・400・429・その他・通信失敗で文言を分ける）
解析status に「解析エラー（画像n）: メッセージ」「保存エラー（画像n）: メッセージ」。APIキー関連のコードは専用の案内文。401はログイン切れ、403は権限・画面の期限切れとして案内
一覧list-status に「エラー: …」「削除エラー: …」
対戦応答の message をそのまま、各区分の状態表示（join-error、pool-status、gen-status など）に表示。通信失敗は「サーバーに接続できませんでした。」、429で message がなければ「回数の上限に達しました。」
