1. 目的・範囲

認証・認可、入力検証、レシート解析・保存、カード生成、ルーム進行、対戦計算、個人情報除去、画面フロントの整合性を自動テストで継続的に検証する。受入（UAT）は 36 で別途行う。

2. テストレベルと手段

レベル対象手段実行コマンド
単体エンジン、サニタイザー、検証器、リミッター、解析ロジックJUnit 5（Spring Boot Test）cd reBack && mvn test
結合（API）認可・CSRF・入力検証・ルーム進行（MockMvc/HTTP）Spring Boot Test + H2（Geminiは呼ばない設定）同上
フロント静的検査管理画面JS・HTMLの整合、テーマ、演出、サーバーnode:test（smoke.test.mjs）node --test reFront/test/smoke.test.mjs
受入利用シナリオ手動（36）—
非機能負荷・セキュリティ診断・アクセシビリティ実機—負荷は実施不可、他は今後の課題（32・33）

3. テスト環境

  • バックエンドのテストはH2のインメモリDB（PostgreSQL不要）、application-test.yml を使用。
  • テストではGeminiを呼ばない設定（application-test.yml の ai-illustration-enabled: false、キーはダミー）。
  • フロントのサーバーテストは localhost:5051 を使用するため、同ポートで別プロセスが動いていないこと。

4. 開始・終了基準

基準内容
開始ビルドが通る。.env なしで mvn test が実行できる
終了（合格）mvn test 全件成功、node --test 全件成功、重大度High以上の未対応不具合なし
保留可Low/Infoで運用承知のもの（30 の「現状維持」）

5. スケジュール・体制

実施は開発者本人が開発期間内に行いました（06・07）。

6. リスク

  • 実Gemini応答に依存する品質（画像の読み取り精度）は自動テストで担保できない。
  • 多端末・多ブラウザーの実機確認は自動化されていない。
  • ローカルの5051番ポート占有でフロントのサーバーテストが不安定になる。
