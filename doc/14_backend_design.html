1. レイヤ構成

レイヤ主要クラス責務
起動ReceiptApplicationSpring Bootアプリケーション起動。
ConfigSecurityConfigパスワードエンコーダー、管理者ユーザー、CSRF、URL単位の認可、未認証時の応答、ログアウト。
ControllerAuthController / ReceiptController / HealthControllerHTTP要求の受付とレスポンス返却。
ServiceReceiptService / GeminiReceiptAnalyzer / ReceiptUploadValidator / GeminiApiKeyPolicy / LoginAttemptLimiter解析・保存の業務処理、Gemini呼び出し、入力検証、ログイン試行制限。
RepositoryReceiptTableRepository / ReceiptTableNameSQL実行、テーブル名の生成・検証。
DTOReceiptText、ReceiptSaveRequest、ReceiptUploadResponse、ReceiptSummary、ReceiptDetail などAPI入出力データ定義（record）。
ExceptionReceiptException / ApiExceptionHandlerHTTPステータス・コード・メッセージを持つ業務例外と、統一エラー応答。

2. 解析処理

  1. ReceiptController が multipart の file と geminiApiKey を受け取る。
  2. ReceiptUploadValidator が空ファイル、サイズ上限、Content-Type を検証する。
  3. ReceiptService が画像のSHA-256を計算する。
  4. GeminiReceiptAnalyzer がAPIキーを検証し、画像とプロンプトをGeminiへ送り、応答を正規化する。
  5. ReceiptTableRepository が画像ハッシュ台帳を確認し、保存済みなら409、未登録なら未保存として記録する。
  6. lines、sha256、structuredData を返す。

3. 保存処理

  1. ReceiptController が JSON の lines、sha256、structuredData を受け取る。
  2. ReceiptService がトランザクション内で、lines が空でないこと、sha256 が64桁の16進数であることを検証する。
  3. ReceiptTableRepository が台帳の未保存行にテーブル名を設定する（更新できなければ409）。
  4. レシートテーブルを作成し、行番号と文字列を一括登録する。
  5. 構造化データの要約と商品を登録する。
  6. テーブル名、行数、行、sha256 を返す。

4. 一覧・詳細・削除処理

  1. 一覧：information_schema から receipt_ で始まる安全な形式のテーブル名を取得し、各テーブルの行数と最大作成日時を返す。
  2. 詳細：テーブル名を検証し、存在しなければ404。行番号順の文字列を返す。
  3. 削除：テーブル名の検証と存在確認の後、トランザクション内でレシートテーブル、構造化データ、台帳の行を削除し、204を返す。

一覧・詳細・削除は ReceiptController から ReceiptTableRepository を直接呼び出す。

5. 認証処理

  1. AuthController が LoginAttemptLimiter で試行枠を確保する（ロック中・上限到達なら429）。
  2. AuthenticationManager がBCryptでパスワードを照合する（失敗なら失敗を記録して401）。
  3. 成功時はセッションIDを変更し、セキュリティコンテキストをセッションへ保存し、ログイン前のCSRFトークンを破棄する。
  4. {"redirect":"/admin/select.html"} を返す。

6. 実装原則

  • 業務エラーは ReceiptException で表し、ApiExceptionHandler で code・message・timestamp のJSONに変換する。
  • SQLの値はプレースホルダーで渡し、テーブル名は receipt_[0-9a-f]{32} の形式を検証してから使う。
  • 秘密情報は環境変数から読み込み、既定値を設けない。
  • Gemini APIキーは要求ごとに受け取り、ログに出力しない。
