1. 選定方針

フロントエンドはフレームワークに依存しない静的ファイルとし、バックエンドはJava/Spring Bootで認証・認可とDBアクセスを構成する。公開は静的サイト（GitHub Pages）とAPI（Render）を分離し、管理画面はセッションCookieを扱うためAPIと同じバックエンドから配信する。

2. 採用技術

分類技術採用理由
フロントエンドHTML5 / CSS3画面構造、フォーム、レスポンシブ表示を標準機能で実装できる。
フロントエンドJavaScript（フレームワークなし）ZIP展開、Fetch API、画面状態の制御をビルドなしで実装できる。
バックエンドJava 21pom.xml の java.version。Dockerイメージも Java 21 を使用する。
バックエンドSpring Boot 4.1.0（Web / Security / JDBC）REST API、セッション認証、CSRF対策、URL単位の認可、JDBCを統合できる。
DBPostgreSQL解析結果を永続保存する。Render上はメジャーバージョン18（render.yml）。
DBアクセスSpring JDBC（JdbcTemplate）レシートごとにテーブルを作成する設計のため、SQLを直接扱う。
AIGoogle Gen AI SDK（google-genai 1.67.0）画像入力と応答JSONスキーマの指定に対応する。
JSON解析Gson 2.13.1Geminiの応答JSONを読み取る。
テストSpring Boot Test / Spring Security Test / H2認証・認可を含むAPIを、PostgreSQLなしでテストできる。
テストNode.js 標準テストランナー（node:test）フロントエンドのHTML・スクリプトの内容を検査する。
実行環境DockerMavenでビルドしたJARをJava 21のJREイメージで実行する。
公開GitHub Pages静的フロントエンドを公開する（config.js に公開URLを設定）。
公開Render（Web Service / PostgreSQL）render.yml でWeb ServiceとDBをまとめて定義できる。

3. 不採用・保留技術

技術判断理由
フロントエンドフレームワーク不採用画面数が少なく、静的ファイルだけで構成できるため。
ORM（JPAなど）不採用テーブル名を動的に生成する設計とJdbcTemplateによるSQL記述を採用しているため。
DBマイグレーションツール未導入テーブルはアプリが実行時に作成している。
CORS設定不採用管理画面をAPIと同じオリジンから配信するため。
フォームログイン・Basic認証無効化JSONのログインAPIとセッションで認証するため。

4. 技術上の制約

  • 解析画像は1ファイル5 MiB（5,242,880バイト）まで、形式はJPEG / PNG。
  • ZIPの展開にはブラウザーの DecompressionStream("deflate-raw") が必要。
  • Gemini APIの利用上限・料金は、利用者が入力するAPIキーの契約に従う。
  • ログイン試行の記録はアプリのメモリ上に保持するため、再起動で消える。
  • 管理者は環境変数で設定する1名。
