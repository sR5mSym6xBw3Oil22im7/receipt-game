35. GitHub Actions・Claude自動ループ 環境構築手順書

1. 本書の位置づけ

本書は、本リポジトリに GitHub Actions による自動検査（ci）と、Claude（Pro契約）によるレビュー・修正の自動ループ（auto-loop）を構築した手順と、動作確認の方法、つまずいた点の対処をまとめたものです。2026-10-19 に実施した内容に基づきます。別のリポジトリや別の端末で同じ環境を再現する場合も、この順に進めます。

  • 自動化の対象：ソースレビュー、レビューの修正、動作確認、デグレード（品質低下）がないことの確認。
  • 運用上の規約と、守衛の判定は、第32章の第6章に記載しています。本書は構築と確認の手順に絞ります。
  • 保存先に秘密情報（トークン、APIキー）を書かないでください。本書にも値は載せていません。
CI でサブスク（Pro）の認証を使う方法は、Claude Code の公式ドキュメント「Claude Code GitHub Actions」が案内しています。利用規約の最新の内容は、実施前に Anthropic の公式の案内で確認してください。

2. 全体像

PRを作るsub01 宛て
→
ci（自動）backend → frontend → readme → doc
→
ラベル auto-loop人が付ける
→
自動ループ検証・レビュー・修正・守衛
→
修正PRauto-fix/<PR番号>
→
人がマージ自動ではマージしない
  • ci はClaudeを使わないため、利用枠を消費しません。
  • 自動ループはラベルを付けたときだけ動き、最大3周の修正と、最後の確認1回を行います。
  • sub01・main へは自動で push しません。

3. 前提

項目内容
GitHub対象リポジトリの管理者権限（Settings を開ける）。リポジトリは同一リポジトリ内のブランチで作業する（forkのPRは自動ループの対象外）
ClaudePro 契約（Pro・Max・Team・Enterprise のいずれか）
端末Linux（Ubuntu 系）。git、curl、Node.js 22、JDK 21、Maven が使えること（手元で検査スクリプトを試す場合）
ツールGitHub CLI（gh）と Claude Code CLI（claude）。第5章で導入する

5. 構築手順

5.1 GitHub CLI（gh）の導入と認証

sudo mkdir -p -m 755 /etc/apt/keyrings
curl -fsSL https://cli.github.com/packages/githubcli-archive-keyring.gpg \
  | sudo tee /etc/apt/keyrings/githubcli-archive-keyring.gpg > /dev/null
sudo chmod go+r /etc/apt/keyrings/githubcli-archive-keyring.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/githubcli-archive-keyring.gpg] https://cli.github.com/packages stable main" \
  | sudo tee /etc/apt/sources.list.d/github-cli.list > /dev/null
sudo apt update && sudo apt install -y gh
gh --version
  1. gh auth login を実行する。
  2. 質問には、GitHub.com → HTTPS → 「Authenticate Git with your GitHub credentials?」は Yes → Login with a web browser を選ぶ。
  3. 表示されたワンタイムコードを、ブラウザーの https://github.com/login/device に入力して許可する。クリップボードの警告は無視してよい。
  4. gh auth status で、スコープに repo と workflow が含まれることを確認する。

「Authenticate Git」で Yes と答えると、git の認証に gh が使われます（gh auth setup-git は不要）。git push が could not read Username で失敗するのは、この認証が未設定のときです。

5.2 Claude Code CLI（claude）の導入

claude コマンドが無い場合（claude: コマンドが見つかりません）に実施します。

curl -fsSL https://claude.ai/install.sh | bash
claude --version

実行ファイルは ~/.local/bin/claude に入ります。~/.local/bin が PATH に無い場合は、新しいターミナルを開くか、export PATH="$HOME/.local/bin:$PATH" を実行します。VS Code 拡張を使っている場合は、拡張に同梱のバイナリー（~/.vscode/extensions/anthropic.claude-code-*/resources/native-binary/claude）を直接実行する方法もあります（バージョンでパスが変わる）。

5.3 Claude GitHub App のインストール

  1. ブラウザーで https://github.com/apps/claude を開き、Install を押す。
  2. Only select repositories を選び、対象のリポジトリだけを指定して許可する。
  3. https://github.com/settings/installations を開き、Claude の Repository access が対象リポジトリのみ（Selected 1 repository）であることを確認する。

claude.ai の「カスタマイズ → コネクタ」にある GitHub 連携は別の機能です。この手順の確認にはなりません。

5.4 トークンの発行と Secret の登録

claude setup-token
gh secret set CLAUDE_CODE_OAUTH_TOKEN
gh secret list
  1. claude setup-token を実行し、ブラウザーで許可する（Pro のアカウント）。ターミナルに sk-ant-oat01-… で始まるトークンが表示される。この画面を閉じる前にコピーする（保存されない）。
  2. gh secret set CLAUDE_CODE_OAUTH_TOKEN を実行し、? Paste your secret に貼り付けて Enter を押す（画面には表示されない）。
  3. gh secret list で、名前 CLAUDE_CODE_OAUTH_TOKEN が出ることを確認する（値は表示されない）。
トークンをコマンドの引数に書かない（シェルの履歴に残る）。チャット、コミット、ログにも貼らない。ANTHROPIC_API_KEY は Secret に登録しない（あると API 課金が優先される）。

トークンの有効期間は1年です。トークンは、setup-token を実行した本人のサブスクに紐づきます。

5.5 リポジトリ設定（Actions による PR 作成の許可）

  1. https://github.com/<ユーザー名>/<リポジトリ名>/settings/actions を開く（個人アカウントの Settings ではなく、リポジトリの Settings → Actions → General）。
  2. Workflow permissions は「Read repository contents and packages permissions」のまま変えない。
  3. その下の Allow GitHub Actions to create and approve pull requests にチェックを入れ、Save を押す。
gh api repos/<ユーザー名>/<リポジトリ名>/actions/permissions/workflow
# 反映後は "can_approve_pull_request_reviews":true と出る

この設定を無効のままにしても動きます。その場合、修正PRは自動では作られず、auto-fix/<PR番号> への push と、PR作成用のリンクのコメントになります。

5.6 ワークフローとスクリプトの配置

パス役割
.github/workflows/ci.ymlpush・PRで backend → frontend → readme → doc を直列に実行（Claude不使用）
.github/workflows/auto-loop.ymlラベル auto-loop で起動。最大3周と最終確認、結果の反映
.github/actions/loop-round/action.yml自動ループの1周分（検証 → レビュー → 判定 → 修正 → 守衛）
scripts/guard.shデグレードの守衛（テスト数、差分、変更禁止パス）
scripts/check_readme.mjsREADME 3ファイルのリンク切れ・秘密情報の検査
scripts/check_doc.mjsdoc/ の noindex・目次・リンク切れ・秘密情報の検査

ファイルの内容は、リポジトリの該当ファイルを参照してください。配置後、手元で検査スクリプトが通ることを確認します。

node scripts/check_readme.mjs
node scripts/check_doc.mjs
(cd reBack && mvn test)
node --test reFront/test/smoke.test.mjs

5.7 ラベルの作成

gh label create auto-loop --description "自動ループ（レビュー）を実行する" --color 1d76db

ラベルは Web の Issues → Labels でも作れます。

5.8 コミットと push

git add .github scripts
git commit -m "GitHub Actions の ci と自動ループを追加"
git push -u origin sub01

push 後、Actions タブ（または gh run list）に ci が表示されます。コミットと push は、本リポジトリの規約どおり、依頼があったときだけ行います。

6. 動作確認

6.1 ci

gh run list --workflow ci --limit 3
gh run view <ID>

4つのジョブ（backend、frontend、readme、doc）が、この順にすべて成功すること。実施時の所要時間は、backend 約44秒、frontend 約9秒、readme 約7秒、doc 約10秒でした。

6.2 自動ループのレビュー

  1. sub01 から試験用ブランチを作り、READMEに1行追加するなどの小さな変更をコミットして push する。
  2. sub01 宛ての PR を作る（タイトルに「試験・マージしない」と入れる）。
  3. PR にラベル auto-loop を付ける。
  4. 数分後、PR に「auto-loop」のコメントが付き、結果が clean、最終レビューの要約が出ることを確認する。

実施時は、レビュー1回が約19秒・4ターンで、API換算で約0.11ドル相当（差分が小さい場合）でした。

6.3 修正ループ

  1. 試験用ブランチで、README に壊れたリンク（存在しない doc/xxx.html へのリンク）を追加して push し、sub01 宛ての PR を作る。
  2. ラベル auto-loop を付ける。
  3. 1周目で検証が不合格になり、Claude が修正し、守衛に合格してコミットされる。2周目で clean になる。
  4. auto-fix/<PR番号> が push され、sub01 宛ての修正PRが作られ、元のPRにコメントが付く。

5.5 の設定が有効なら修正PRは自動で作られ、無効ならPR作成用のリンクがコメントされます。いずれの場合も sub01 は変わりません。

6.4 後片付け

gh pr close <修正PRの番号> -d -c "試験終了"
gh pr close <試験PRの番号> -d -c "試験終了"
git fetch --prune

-d でブランチも削除されます。試験用の PR とブランチは、マージせずに閉じます。

7. 構成上の決定事項

決定理由
認証はサブスク（Pro）のみ。APIキーへは切り替えないAPIキーを使うと従量課金になるため。CLAUDE_CODE_OAUTH_TOKEN を使う
claude-code-action に github_token を明示して渡す既定のGitHub App認証では、ワークフローが既定ブランチ（main）にないとスキップされる（Workflow validation）。main へ入れずに動かすため
レビューのClaudeは読み取り専用編集・コメント投稿・push のツールを許可しない。コメントはワークフローが投稿する
修正のClaudeは commit・push をしないコミットは守衛に合格した後に、ワークフローが行う
.github/・scripts/ は自動修正の対象外Claudeが検査そのものを書き換えて通す抜け道を防ぐ（守衛が不合格にする）
同一リポジトリのPRだけを対象にするforkのPRにSecretを渡さない
sub01・main へ自動で push しない修正は auto-fix/<PR番号> に分け、マージは人が判断する

8. トラブルシューティング

症状原因対処
claude: コマンドが見つかりませんClaude Code CLI が未導入、または PATH に無い5.2 を実施。新しいターミナルを開く
bash: history: …/.bash_history: 制限されています履歴ファイルへの書き込みの警告動作に影響なし。無視してよい。なお bash -r は制限付きシェルを起動するコマンドなので、hash -r と取り違えて入力しない
git push が could not read Username で失敗git の認証が未設定5.1 の gh auth login（Authenticate Git は Yes）を実施
Claude のステップが Skipping action due to workflow validation でスキップされ、レビューが空既定ブランチにワークフローが無い（GitHub App認証の検証）github_token を明示して渡す（実装済み）
修正PRが作られず、「PRを作る」のリンクがコメントされる5.5 の設定が無効5.5 を実施する。または、リンクからPRを作る
ラベルを付け直しても、古いワークフローで動くpull_request イベントは、PRのマージ結果にあるワークフローを使う。試験ブランチが古い土台のままベースブランチ（sub01）を試験ブランチに取り込んで push してから、ラベルを外して付け直す
ラベルを付けても起動しないすでにラベルが付いている（labeled イベントが出ない）ラベルを一度外してから付ける
修正PRや auto-fix/… への push で ci が動かないGITHUB_TOKEN による push・PR作成では、後続のワークフローが起動しない仕様ループ内で同じ4検査を実行済み。必要なら ci.yml に workflow_dispatch を足して手動実行する
認証エラートークンの失効、またはAPIキーが優先されているclaude setup-token でトークンを再発行して Secret を更新する。ANTHROPIC_API_KEY の Secret があれば削除する
利用制限に達したPro の枠は手元の利用と共有ラベルを付ける頻度を減らす。時間をおいて再実行する

9. 運用と保守

  • トークンは1年で失効します。2027年10月ごろに、5.4 をやり直して Secret を更新してください。
  • Pro の利用枠は、CIでの消費量を確認できません。ラベルによる手動起動で、使いすぎを防ぎます。
  • .github/ と scripts/ の変更は人が行い、ci.yml と試験用PRで確認します。
  • 現在の警告：actions/checkout@v4・actions/setup-node@v4 が Node.js 20 を使う旨の非推奨、actions/setup-java@v4 の更新終了、ubuntu-latest の Ubuntu 26 への切り替え。動作には影響しません（未対応）。
  • ブランチ保護（ci の成功を必須にする）は未導入です。導入すると sub01 への直接 push ができなくなり、自動ループのPRで ci が自動起動しないため、先に手動実行の追加が必要です（第34章の K-12）。
