33. 操作マニュアル・運用保守手順書

1. 基本操作（プレイヤー）

  1. メニューで「モンスターレシート対戦」を開く。
  2. ルームを作る場合は「ルームを作る」を押し、表示された6桁のコードを相手に伝える（「コピー」でコピーできる）。参加する場合はコードを入力して「参加」を押す。
  3. 相手が来なければ90秒でコンピュータ対戦になる。
  4. 「▶ このレシートを選ぶ」でレシートをめくると、モンスターカードが手札に入る（最大3枚）。めくる前なら「シャッフル」で配り直せる（有効なカードが10枚以上のとき）。
  5. 「レシート画像から作る」タブで、自分のレシート画像（JPEG / PNG、5 MiBまで）からカードを1枚作れる。
  6. 手札または作ったカードを1枚選び、「このカードで決定」を押す。相手も決めると対戦が始まる。
  7. 対戦は自動で進む。「速度」で速さを変え、「結果までスキップ」で結果へ進める。
  8. 結果画面で「同じルームで再戦」または「ロビーへ」を選ぶ。

2. レシート解析（管理者）

  1. メニューの「管理者ログイン」からログインする。
  2. 管理者メニューで「レシート解析」を開く。
  3. レシート画像（JPEG / PNG）、またはそれらだけを入れたZIPを選ぶ（ドロップも可）。
  4. 「解析」を押す。1枚につき数十秒かかることがある。
  5. 表示された文字列を確認し、「データベースへ保存」を押す。
  6. 「保存済みレシートを確認する」で一覧を開き、「参照」で内容を確認する。不要なものはチェックして「チェックしたレシートを削除」を押す。

3. 解析状態の見方

表示意味対処
画像n/mを解析中です（s秒経過）Gemini の応答待ちそのまま待つ（最大210秒）
n枚の解析が完了しました。すべて成功内容を確認して保存する
Gemini APIの利用上限に達しました。Gemini の上限少し待って同じ画像で再解析する
Gemini APIキーが利用できません／設定されていません。サーバーのキーの問題reBack/.env または Render の GEMINI_API_ANALYZE／GEMINI_API_DEFAULT を確認する
同じレシート画像は既にPostgreSQLへ登録されています。保存済みの画像保存は不要
個人情報の確認ができなかったため保存できません。個人情報を取り除けなかったその画像は保存しない
バックエンドサーバーから応答がありません。通信・Render の停止Render の状態を確認して再実行する
ログインの有効期限が切れました。セッション切れログインし直す

4. トラブルシューティング

症状原因対処
バックエンドが起動しない（GEMINI_API_DEFAULT is required）既定のキーが未設定reBack/.env または環境変数に GEMINI_API_DEFAULT を設定する
バックエンドがDBに接続できないPostgreSQL が止まっている、接続情報の違いdocker ps で receipt-game-db を確認し、docker restart receipt-game-db。DB_PORT（Docker なら55432）を確認する

対戦画面を開くとメニューに戻る直接アクセス（アドレスバー・ブックマーク）メニューのリンクから開く
「このルームの席がありません」席トークンがない・別のルームロビーからやり直す
「回数の上限に達しました」IPごとの回数制限時間をおく
画像からカードを作れない（本日の上限）Gemini のキーごとの1日の上限、IPごとの上限レシートを選んで対戦する。翌日（日本時間）に戻る
スモークテストの server.mjs のテストだけ失敗するポート5051を別の server.mjs が使っているss -ltnp | grep 5051 で確認し、そのプロセスを止めて再実行する
Render の画面が開くまで遅いFree プランの停止からの起動しばらく待つ

5. 運用保守

5.1 定期的な確認

  • Render のログで、Gemini の上限・キーの拒否、DB の障害、カードの再点検の結果を確認する。
  • Gemini の利用量と上限（Google 側の設定）を確認する。

5.2 フォルダのレシートをまとめて取り込む

cd reBack
mvn spring-boot:run -Dspring-boot.run.profiles=local \
  -Dspring-boot.run.arguments="--app.batch-import.dir=/path/to/receipts"
  • フォルダ内の .jpg／.jpeg／.png を名前順に1件ずつ解析・保存し、終わったらアプリを終了する。保存済みの画像は飛ばす。
  • 結果は log/batch-import.tsv に追記する。終了コード：0 成功、1 失敗あり、2 Gemini の上限で途中停止（上限の回復後に再実行すれば続きから）。
  • 主なオプション：app.batch-import.report、app.batch-import.max-attempts（既定5）、app.batch-import.interval-seconds（既定5）。

5.3 カードを生成AIで作り直す

cd reBack
mvn spring-boot:run -Dspring-boot.run.profiles=local \
  -Dspring-boot.run.arguments="--app.monster-batch.enabled=true"
  • 保存済みレシートのカードを古い順に作り直して終了する。log/monster-batch.tsv に SAVED と記録されたレシートは飛ばす。
  • 終了コード：0 すべて SAVED、1 PARTIAL（一部が計算式・代替イラスト）・FAILED あり、2 生成AIが3件続けて使えず停止。
  • 主なオプション：app.monster-batch.report、max-attempts（既定3）、interval-seconds（既定5）、retry-wait-seconds（既定60）。

5.4 その他

  • 管理者のパスワードを変えるときは、BCrypt のハッシュを作って ADMIN_PASSWORD_HASH を差し替え、再起動する。
  • Gemini のキーを替えるときは、環境変数を差し替えて再起動する。
  • テーマを足す・変えるときは reBack 側の theme/ を直し、reFront/theme/ にコピーする。

6. プライバシー

  • レシート画像は保存しない。保存する文字列・構造化データからは個人情報を取り除く。
  • 対戦では、相手にレシートの内容（店舗・日時・商品・合計・支払方法・レシート番号）が見える。個人情報は表示されない。
  • 画像からカードを作るとき、読み取った内容はそのルームの間だけ保持する。
  • ログにはレシートの内容・APIキー・パスワードを残さない。
