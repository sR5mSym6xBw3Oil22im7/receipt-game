34. 要確認事項・検討課題事項

1. 基本操作

  • メニュー（GitHub Pages）から、対戦・デモ・管理者ログイン・動画へ進む。
  • メニュー以外を直接開くとメニューへ戻される。

2. 対戦のしかた（プレイヤー）

  1. 「ルームを作る」を押し、表示された6文字のルームコードを相手に伝える。相手はコードを入力して参加する。
  2. 90秒以内に相手が来なければ、コンピューターと対戦する。
  3. 9枚のレシートをめくって、最大3枚を手札にする。10枚以上あるときはシャッフルできる。「レシート画像から作る」で1体だけ作ることもできる。
  4. 手札から1枚を決めて「決定」を押す。双方が決めると自動で対戦が始まる。
  5. 速度の変更やスキップができる。結果画面で両者の元レシートが表示され、再戦もできる。

3. 管理者の操作

  1. ログインする（5回失敗すると15分ロックされる）。
  2. 「レシート解析」でJPEG/PNG（5 MiB以内）またはZIPを選び、[解析] を押す。
  3. 結果を確認する。誤読があれば保存しない。個人情報が含まれていないか確認する。
  4. [データベースへ保存] を押す。保存して初めて登録され、カードが有効になる。「同じレシート画像は既に登録されています」は重複で、保存は不要。
  5. 「保存済みレシートを確認する」で一覧・詳細を見る。削除はチェックして [チェックしたレシートを削除]。カードも削除され、元に戻せない。

4. トラブルシューティング

症状原因と対処
ログインできない（429）失敗が5回に達した。15分待つか、バックエンドを再起動するとロックが解除される。
解析が失敗するAPIキー未設定・拒否・上限超過の可能性。Renderの環境変数とGeminiの利用状況を確認する。
対戦を始められない有効なカードが2枚未満。レシートを保存する（または画像からカードを作る）。
画面が古い?v= が更新されていない可能性。強制再読み込みを行う。
バックエンドに接続できないRenderの無料プランが停止している場合がある。/api/health を開いて起動を待つ。

5. 運用保守

  • 稼働確認：/api/health。
  • サービスを再起動・停止する前に、実際に何で動いているか（docker ps、ps）を確認する。ローカルDBの再起動は docker restart receipt-game-db。
  • ログ：reBack/log/backend.log（日次ZIP）。
  • 起動時にカードのない保存済みレシートへカードを作る（MONSTER_BACKFILL_ON_STARTUP）。
  • Renderのサービス名を変えたら reFront/config.js も変更する。

6. プライバシー

  • 画像ファイルは保存されない。
  • 保存前に個人情報が「（非表示）」に置換される。
  • 対戦の結果画面では、両者の元レシートの内容が相手に表示される。個人情報が写っていない画像だけを使うこと。
