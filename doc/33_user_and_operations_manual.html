33. 操作マニュアル・運用保守手順書

1. 基本操作

  1. ブラウザーでメニュー画面（https://sr5msym6xbw3oil22im7.github.io/receipt-analysis/reFront/index.html）を開きます。
  2. 「デモを試す」で、APIキーなしで解析の流れを確認できます。
  3. 「レシートを解析」または「保存済みレシートを確認する」を押すと、ログイン画面が開きます。
  4. ユーザーIDとパスワードを入力して「ログイン」を押します。
ボタン用途
画像解析（デモ）固定データの解析結果を表示する。
解析選んだ画像をGeminiで解析する。DBには保存しない。

入力を消去APIキーの入力欄を空にする。
参照保存済みレシートの詳細を表示する。

2. レシート解析

  1. 解析画面で、レシート画像（JPEG / PNG）を枠へドラッグ＆ドロップするか、枠を押して選びます。複数のレシートはJPEG / PNGだけを入れたZIPで指定できます。
  2. 「Gemini APIキー」にAPIキーを入力します。
  3. 「解析」を押します。15秒ごとに経過時間が表示されます。
  4. 結果を確認し、「PostgreSQLへ保存」を押します。
  5. すべて保存されると画面が初期状態に戻ります（APIキーは入力されたまま残ります）。

3. 解析状態の見方

表示意味
画像を選ぶ初期状態。ファイルを選び直したときもこの状態に戻る。
解析する解析中。ボタンは「解析中...」で押せない。
内容を確認すべての画像の解析が完了。保存ボタンが表示される。
PostgreSQLへ保存保存中。ボタンは「保存中...」で押せない。

4. トラブルシューティング

症状確認・対応
「Gemini APIの利用上限に達しました」時間をおくか、別のAPIキーに入れ替えて、同じ画像のまま再度解析する。
「Gemini APIキーが利用できません」正しいAPIキーに入れ替えて再度解析する。
「レシートから文字を読み取れませんでした」レシート全体がはっきり写った画像で再度解析する。
「同じレシート画像は既に…登録されています」保存済みの画像。一覧で確認する。登録し直す場合は先に削除する。
「バックエンドサーバーから応答がありません」通信状態を確認し、/api/health が応答するか確認してから再実行する。
「ログインの有効期限が切れました」ログインし直す。
「ログインの失敗が続いたため…」ロック時間（既定15分）が過ぎてからログインする。
「このブラウザはZIP解凍に対応していません」最新のブラウザーで実行する。

5. 運用保守

  • 稼働確認は /api/health が {"status":"UP"} を返すことで行う。
  • 管理者のパスワードを変える場合は、新しいBCryptハッシュを ADMIN_PASSWORD_HASH に設定して再起動する。
  • ログイン制限の回数・時間は LOGIN_MAX_FAILURES・LOGIN_LOCK_MINUTES で変更できる。ロックはアプリの再起動でも解除される。
  • Geminiのモデルは application.yml の gemini.receipt-model で変更する。
  • 画像サイズの上限を変える場合は、app.max-upload-bytes と spring.servlet.multipart の上限を合わせて変更する。
  • Gemini解析の失敗はログ（本番は標準出力、localプロファイルは log/backend.log）で確認する。
  • 画面の文言を変える場合は、reFront/ と static/admin/ の両方を更新し、スモークテストを実行する。

6. プライバシー

  • レシート画像はサーバーに保存しません。重複判定用のSHA-256と、読み取った文字列・構造化データだけを保存します。
  • Gemini APIキーは保存しません。共有のパソコンでは、使用後に「入力を消去」とログアウトを行ってください。
  • 画像は解析のためGoogle Gemini APIへ送信されます。
  • 保存したデータは管理者だけが参照・削除できます。不要になったデータは削除してください。
