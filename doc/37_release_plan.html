2. 手順（初回デプロイ）

  1. Renderで reBack/render.yml からBlueprintを作成する（Webサービス receipt-game、PostgreSQL receipt-analysis-psl-service）。
  2. sync: false の環境変数を手動設定する：ADMIN_USERNAME、ADMIN_PASSWORD_HASH、GEMINI_API_DEFAULT、GEMINI_API_PLAYER1/2、GEMINI_API_MONSTER、GEMINI_API_ANALYZE（用途別は任意。未設定なら DEFAULT を使う）。
  3. デプロイ完了後、https://<サービス>.onrender.com/api/health が {"status":"UP"} を返すことを確認する。
  4. サービス名を変えた場合は reFront/config.js の backendBaseUrl を新しいURLにし、フロントを再配信する。
  5. フロント（reFront/）をGitHub Pagesで公開する（ルートの index.html が reFront/index.html へ転送）。
  6. バックエンドの app.frontend.menu-url が公開メニューURLと一致していることを確認する（直接アクセスの転送先）。

3. 手順（更新リリース）

  1. 作業ブランチで変更し、テストを通す。
  2. 同期が必要なファイル・?v= を確認（20）。
  3. main へ反映（コミット・プッシュは明示的に指示したときだけ行う）。
  4. Renderが自動/手動でデプロイ。ログで起動完了（Started ReceiptApplication）を確認。
  5. 起動時のバックフィル（MONSTER_BACKFILL_ON_STARTUP）が走るため、保存済みレシートが多い場合は初回の起動時間が延びうる。
  6. 下記4章の確認を実施。

5. 注意

  • 本番ではHTTPSかつ SESSION_COOKIE_SECURE=true（既定）。false はローカル専用。
  • MONSTER_TRUST_FORWARDED_FOR=true はプロキシ背後（Render）でのみ。
  • ログイン失敗・回数制限の記録は再起動で消える。
