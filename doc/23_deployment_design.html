1. 配置方針

対象配置先配置単位
フロントエンドGitHub PagesreFront ディレクトリの静的HTML/CSS/JS/画像（ルートの index.html は reFront/index.html へ転送）
バックエンドRender Web ServicereBack を Docker でビルドした Java アプリ（管理画面を含む）
データベースRender PostgreSQLreceipt-analysis-psl-service
設定Render 環境変数管理者、Cookie、DB接続

2. バックエンドDockerビルド

  1. maven:3.9.11-eclipse-temurin-21-alpine で pom.xml をコピーし、mvn -q -DskipTests dependency:go-offline を実行する。
  2. src をコピーし、mvn -q -DskipTests package で JAR を生成する。
  3. eclipse-temurin:21-jre-alpine へ target/receipt-backend-0.0.1-SNAPSHOT.jar を app.jar としてコピーする。
  4. 8081 を EXPOSE し、java -jar app.jar で起動する。

4. GitHub Pages

  • リポジトリの静的ファイルを GitHub Pages で配信する。
  • 公開URLの reFront/index.html をエントリとする（https://sr5msym6xbw3oil22im7.github.io/receipt-analysis/reFront/index.html）。
  • reFront/config.js の公開用バックエンドURLが Render のサービスURLを指すことを確認する。

5. デプロイ後確認

  1. バックエンドの /api/health が {"status":"UP"} を返す。
  2. メニュー、デモ画面が表示され、画像・CSS・JavaScriptが読み込まれる。
  3. 管理画面のログイン画面が表示され、ログインできる。
  4. 保存済みレシート一覧が表示される。
  5. ログアウト後、/admin/select.html がログイン画面へリダイレクトされる。

6. ロールバック

  • 不具合が見つかった場合は、直前のコミットへ戻す変更を main に反映し、再デプロイする。
  • テーブル定義はアプリが実行時に作成するため、コードを戻してもDBのテーブルは残る。データの削除が必要な場合は管理画面から行う。
