1. 配置方針

対象配置先方法
reFront/、index.html、404.htmlGitHub Pages（リポジトリ receipt-game）main ブランチの内容を公開
reBack/Render Web Service（receipt-game、Docker、Free）render.yml（Blueprint）、rootDir: reBack
DBRender PostgreSQL（receipt-analysis-psl-service、Free、PostgreSQL 18）render.yml の databases

2. バックエンドDockerビルド

FROM maven:3.9.11-eclipse-temurin-21-alpine AS build
WORKDIR /app
COPY pom.xml ./
RUN mvn -q -DskipTests dependency:go-offline
COPY src ./src
RUN mvn -q -DskipTests package

FROM eclipse-temurin:21-jre-alpine
WORKDIR /app
RUN addgroup -S app && adduser -S app -G app
COPY --from=build /app/target/receipt-backend-0.0.1-SNAPSHOT.jar app.jar
USER app
EXPOSE 8081
ENTRYPOINT ["java", "-XX:MaxRAMPercentage=70", "-XX:+ExitOnOutOfMemoryError", "-jar", "app.jar"]
  • 依存関係を先に取得し、ソースだけの変更でキャッシュを使えるようにする。
  • テストはイメージのビルドでは実行しない（リリース前にローカルで実行する）。
  • .dockerignore で target、.git、.idea、.vscode、*.log、.env を除外する。

No確認期待

6. ロールバック

  • バックエンド：Renderのダッシュボードで前のデプロイを選んで再デプロイする。または、問題のコミットを revert して push する。
  • フロントエンド：問題のコミットを revert して push する（GitHub Pages が再公開する）。
  • DB：テーブルはアプリが作るだけで、既存の列は変えない（追加の制約・列だけ）。データの復元はRenderのバックアップ機能の範囲で行う（Freeプランの制約に注意）。
