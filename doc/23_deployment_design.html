1. 配置方針

対象配置先
reFront/（メニュー・動画・テーマ）GitHub Pages（ルートの index.html が reFront/index.html へ転送、404.html が不明なURLをメニューへ転送）
reBack/（API・管理画面・対戦・デモ）Render Web Service（Docker）
DBRender PostgreSQL

2. バックエンドDockerビルド

  • ビルド：maven:3.9.11-eclipse-temurin-21-alpine（mvn -DskipTests package）。
  • 実行：eclipse-temurin:21-jre-alpine、非rootユーザー app、EXPOSE 8081。
  • 起動：java -XX:MaxRAMPercentage=70 -XX:+ExitOnOutOfMemoryError -jar app.jar。メモリ不足時は終了して再起動させる。

3. Render設定（reBack/render.yml）

リソース設定
Webサービス名前 receipt-game、docker、rootDir reBack、plan free、healthCheckPath /api/health
PostgreSQL名前 receipt-analysis-psl-service、plan free、メジャー18、ipAllowList: []（外部接続不可）
環境変数第22章のとおり

サービス名はRenderの公開ホスト名（<name>.onrender.com）を決めるため、reFront/config.js と常に一致させる。

4. GitHub Pages

  • リポジトリを公開し、メニューは …/receipt-game/reFront/index.html。
  • バックエンドの接続先は config.js の backendBaseUrl。

5. デプロイ後確認

  1. /api/health が {"status":"UP"} を返す。
  2. メニューから対戦・デモ・管理者ログインの各画面が開く。
  3. 管理者でログインできる。
  4. デモで対戦を最後まで進められる。

6. ロールバック

  • 直前の正常なコミットをRenderで再デプロイする。
  • DBのテーブルはアプリが追加するだけで、既存テーブルの形は変えない（IF NOT EXISTS）。
  • 環境変数を変えた場合は元の値に戻す。
