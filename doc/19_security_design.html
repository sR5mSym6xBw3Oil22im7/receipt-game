1. セキュリティ方針

データ操作を管理者に限定し、認可をバックエンドで行う。更新要求はCSRFトークンで保護し、パスワードの総当たりを遅らせる。画像ファイルとGemini APIキーは保存せず、秘密情報は環境変数で管理する。

2. 対策一覧

脅威・課題対策実装箇所
未認証のデータ操作/api/receipts 配下は HTTPメソッドを問わず ROLE_ADMIN を要求。管理画面（ログイン画面と共通ファイルを除く /admin/ 配下）も ROLE_ADMIN。SecurityConfig
意図しないAPI公開許可したもの以外の /api/** を denyAll。SecurityConfig
CSRFCookieに保存したトークンを X-XSRF-TOKEN ヘッダーで照合。ログイン時にトークンを破棄。SecurityConfig / AuthController / admin-api.js
パスワードの総当たりユーザーIDごとに連続失敗が上限に達したら一定時間429。照合前に試行枠を確保し、照合中の要求も数える。LoginAttemptLimiter
パスワードの平文保存BCryptハッシュを環境変数で設定。SecurityConfig
セッション固定ログイン成功時にセッションIDを変更。AuthController
Cookieの盗用HttpOnly、SameSite=Lax、Secure（SESSION_COOKIE_SECURE、既定true）。application.yml / SecurityConfig
SQLインジェクション値はプレースホルダー。動的テーブル名は receipt_[0-9a-f]{32} のみ許可。ReceiptTableRepository / ReceiptTableName
XSSAPIから受け取った文字列は textContent で表示。app.js / select.js
不正なファイルAPIで空・サイズ・Content-Type を検証。画面で先頭バイトを確認。ZIPは画像以外・暗号化・未対応圧縮を拒否。ReceiptUploadValidator / app.js
APIキーの漏えい要求ごとに受け取り、保存・ログ出力しない。画面の入力欄は伏字。GeminiReceiptAnalyzer / upload.html
内部情報の露出予期しない例外は固定メッセージの500にする。ApiExceptionHandler

3. 秘密情報

情報保存場所公開禁止
DBパスワード環境変数 DB_PASSWORD（Renderではデータベースから設定）必須
管理者ユーザーID環境変数 ADMIN_USERNAME必須
管理者パスワードハッシュ環境変数 ADMIN_PASSWORD_HASH必須
Gemini APIキー保存しない（画面の入力欄のみ）必須
ローカルの .envリポジトリ直下（.gitignore で管理対象外）必須

4. 残存リスク

  • ログイン試行の記録はアプリのメモリ上にあり、再起動で消える。複数インスタンスでは共有されない。
  • 保存済みかどうかの確認はGemini解析の後に行うため、保存済み画像の再解析でもGeminiの利用枠を消費する。
  • 解析済み・未保存の画像ハッシュは台帳に残り続ける。
  • 画面はGoogle Fontsを外部から読み込む。
