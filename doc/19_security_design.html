1. セキュリティ方針

  • 既定で拒否し、必要なものだけ公開する。
  • AIの出力とアップロードを信用せず、検証してから使う。
  • 個人情報とシークレットを保存・出力しない。
  • 対戦はサーバーで計算し、ブラウザーを信用しない。

2. 対策一覧

区分対策
認可公開：/api/health、/api/auth/csrf|login|session、/api/monster/**、ログイン用の静的ファイル。管理者のみ：/api/receipts/**（メソッドを問わない）、/admin/**。その他の /api/** は管理者でも拒否。
CSRFXSRF-TOKENクッキー（SameSite=Lax）＋X-XSRF-TOKEN。/api/receipts はログイン済みのとき必須。/api/monster/** はCookieを使わないため対象外。
セッションHttpOnly、SameSite=Lax、本番は Secure。ログイン成功でセッションIDを変更。
ログイン保護同一ユーザー名で5回失敗→15分ロック（429）。ロック中は正しいパスワードでも照合しない。ユーザー名は大小文字・前後空白を無視し、SHA-256化。追跡数に上限（10,000）。
アップロードJPEG/PNGのみ。Content-Type・先頭バイト・画素数を検査。ZIPはブラウザーで展開し件数・サイズに上限。
SQLテーブル名は receipt_[0-9a-f]{32} のみ許可。
個人情報氏名・電話番号・住所・メール・会員番号・カード番号等を保存前に「（非表示）」へ置換。取り除けなければ保存しない。ログは件数のみ。
AI出力SVGの許可リスト検証、img のdata URIで表示（スクリプトは実行されない）、名前・説明の検証、数値の丸め。
ヘッダーCSP（default-src 'none'、script-src 'self' ほか）、Referrer-Policy: no-referrer、Permissions-Policy（camera/microphone/geolocation 無効）、本番はHSTS。
対戦の不正対策相手のカードを対戦開始まで返さない。席トークンはSHA-256ハッシュのみDB保存。ルームの有無を推測させない403。
濫用対策IP別の回数制限（IPは起動ごとの乱数を混ぜたハッシュでメモリ保持）、Geminiのキー別日次上限。

3. 秘密情報

  • Gemini APIキー、管理者のパスワードハッシュ、DB接続情報はリポジトリに含めない。reBack/.env はGit管理外。
  • Renderでは sync: false の環境変数を手動で設定する。
  • MONSTER_TRUST_FORWARDED_FOR はプロキシ背後でのみ true にする（X-Forwarded-For の末尾をIPとして使うため）。

4. 残存リスク

リスク内容対応状況
ロックが本人にも効くユーザー名単位のロックのため、攻撃中は管理者本人も15分ログインできない。仕様として受け入れ。再起動で解除
記録がメモリ上のみログイン失敗・回数制限の記録は再起動で消え、複数台で共有されない。検討課題（第34章）
個人情報の未検出市区町村だけの住所、22桁の数字、(at) 表記は検出しない。検討課題（第34章）
ウイルス検査しない。型検査のみ。画像ヘッダーにEICAR文字列を追記したファイルは通過する。検討課題（第34章）
対戦結果での元レシート表示結果画面で両者の元レシートの内容が相手に見える。検討課題（第34章）
画像のAI学習への利用画像をGoogleのGemini APIへ送る。無料枠のキーでは、送った内容がGoogleのサービス改善（AIの学習を含む）に使われることがある。画像はEXIFを除去せずに送る。3か所に注意書きを表示（第18章）。有料枠の確認とEXIF除去は検討課題
