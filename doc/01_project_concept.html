1. 企画の狙い

日常で受け取る「レシート」を、遊べるモンスターカードに変えるWebゲームです。レシート画像をGoogle Geminiで読み取って保存し、保存済みレシートから生成したモンスターカードで2人（または対コンピューター）が対戦します。「買い物の記録が、世界に一枚のモンスターになる」ことを体験の核にします。

項目内容
タイトルモンスターレシート対戦（Monster Receipt Battle）
ジャンルカード対戦（自動戦闘）／Webブラウザーゲーム
プレイ人数1〜2人（2人目が90秒以内に参加しなければコンピューターが相手）
プレイ環境PC・スマートフォンのブラウザー（ログイン不要）
収益モデルなし（課金・広告・ガチャ要素は実装していない）
版0.0.1-SNAPSHOT

2. ターゲット

  • 友人・家族と短時間（1戦数分）で遊びたいカジュアル層。
  • レシート画像から自分だけのカードができる意外性を楽しみたい層。
  • 採用担当者・面接官・現場エンジニアによる、AI連携型Webアプリケーションの設計・実装力の確認（卒業ポートフォリオとしての閲覧・動作確認）。
個人開発の卒業ポートフォリオのため、想定ユーザー数・KPI・目標売上などの事業計画値は設定していません。

3. 差別化点

No差別化点実現方法（根拠）
1実在のレシートがカードになる画像のSHA-256の先頭32bitを乱数の種にし、金額・品数・文字数・購入時刻などから能力値を計算（MonsterCardGenerator）
2同じレシートは必ず同じカード名前・能力値は画像ハッシュと内容だけで決まる（イラストのみ作成時刻で変化）
3AIによるカード演出Geminiがモンスター名・技・説明文・SVGイラストを作成。失敗時は計算式の値と代替イラストへ自動で切替
4ログイン不要・すぐ遊べるルームコード6桁と席トークンで参加。管理者ログインは解析・保存側のみ
5安全性への配慮保存前に個人情報（氏名・電話・会員番号・住所・メール・カード番号）を「（非表示）」に置換。取り除けなければ保存しない
6日替わりデザイン10種類のテーマが毎日3:00（JST）に順番に切り替わる
7対戦は公平・改ざん困難勝敗はサーバーで計算。相手のカードは対戦開始まで応答に含めない

4. ゲームの流れ（概要）

管理者がレシートを解析画像→Gemini→確認
→
PostgreSQLへ保存カードが有効になる
→
プレイヤーがルーム作成/参加コード6桁
→
9枚の中から最大3枚を選ぶまたは画像から作成
→
1枚決定→自動対戦サーバーで勝敗計算
