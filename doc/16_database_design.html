1. データベース概要

項目内容
DBMSPostgreSQL（Render上はメジャーバージョン18）
JDBC URLjdbc:postgresql://${DB_HOST:localhost}:${DB_PORT:5432}/${DB_NAME:receipt_db}
ユーザー${DB_USER:postgres}（パスワードは DB_PASSWORD、既定値なし）
スキーマ初期化スキーマ定義ファイルは使わず、アプリが処理の実行時に CREATE TABLE / CREATE TABLE IF NOT EXISTS を実行する
スキーマpublic
テスト用DBH2（jdbc:h2:mem:receipt;MODE=PostgreSQL;DATABASE_TO_LOWER=TRUE;DB_CLOSE_DELAY=-1）
保持期間管理者が削除するまで

2. receipt_image_hash_registryテーブル

カラム型NULL制約／初期値説明
image_sha256VARCHAR(64)不可PK画像のSHA-256（小文字16進数）
table_nameVARCHAR(64)可UNIQUE保存先のレシートテーブル名。NULLは解析済み・未保存
created_atTIMESTAMP WITH TIME ZONE不可DEFAULT CURRENT_TIMESTAMP登録日時

3. receipt_（32桁の16進数）テーブル

レシート1件ごとに1テーブルを作成する。テーブル名は「receipt_」＋UUID（ハイフンを除いた32桁）。

カラム型NULL制約／初期値説明
idBIGINT不可GENERATED BY DEFAULT AS IDENTITY / PK連番
line_noINTEGER不可行番号（1始まり）
textTEXT不可読み取った文字列
created_atTIMESTAMP WITH TIME ZONE不可DEFAULT CURRENT_TIMESTAMP登録日時

4. receipt_structured_summaryテーブル

カラム型NULL制約／初期値説明
idBIGINT不可IDENTITY / PK連番
receipt_table_nameVARCHAR(64)不可UNIQUEレシートテーブル名
image_sha256VARCHAR(64)不可UNIQUE画像のSHA-256
store_nameVARCHAR(255)可店舗名
branch_nameVARCHAR(255)可支店名
store_categoryVARCHAR(50)可店舗カテゴリ
purchased_atTIMESTAMP可購入日時
total_amountBIGINT可合計金額
payment_methodVARCHAR(100)可支払方法
receipt_numberVARCHAR(100)可レシート番号
created_atTIMESTAMP WITH TIME ZONE不可DEFAULT CURRENT_TIMESTAMP登録日時

5. receipt_structured_itemテーブル

カラム型NULL制約／初期値説明
idBIGINT不可IDENTITY / PK連番
receipt_table_nameVARCHAR(64)不可FK（fk_receipt_structured_item_summary）→ receipt_structured_summary.receipt_table_name、ON DELETE CASCADEレシートテーブル名
item_noINTEGER不可UNIQUE（receipt_table_name, item_no）商品番号（1始まり）
item_nameTEXT不可商品名
categoryVARCHAR(50)不可商品カテゴリ（値がない場合は「その他」）
quantityNUMERIC(12,3)可数量
unit_priceBIGINT可単価
amountBIGINT可金額
created_atTIMESTAMP WITH TIME ZONE不可DEFAULT CURRENT_TIMESTAMP登録日時

6. CRUD

処理SQL概要並び順
解析（台帳記録）receipt_image_hash_registry を SELECT し、未登録なら table_name を NULL で INSERT—
保存台帳を UPDATE（table_name IS NULL の行にテーブル名を設定）→ CREATE TABLE → 行を INSERT（バッチ）→ 要約・商品を INSERT—
一覧information_schema.tables から receipt_ で始まるテーブル名を取得し、各テーブルで COUNT(*)・MAX(created_at)テーブル名の降順
詳細SELECT line_no, text FROM レシートテーブルline_no 昇順
削除DROP TABLE → 商品・要約を DELETE → 台帳を DELETE—

7. データ設計上の注意

  • テーブル名をSQLへ連結する処理では、receipt_[0-9a-f]{32} に一致することを必ず確認する。一致しない場合は500 UNSAFE_TABLE_NAME とする。
  • 台帳・要約とレシートテーブルの間には外部キーがない。保存・削除をトランザクションで行い整合性を保つ。
  • 構造化データのテーブルを準備するとき、要約のない商品行を削除し、外部キーがなければ追加する。
  • 解析済み・未保存（table_name が NULL）の台帳行を削除する処理はない。
  • 画像ファイルとGemini APIキーはDBに保存しない。
