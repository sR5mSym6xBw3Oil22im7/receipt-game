1. データベース概要

  • PostgreSQL。テーブルはアプリが実行時に CREATE TABLE IF NOT EXISTS で作成する（手動のDDL実行は不要）。
  • レシートごとに receipt_ + 32桁16進数のテーブルを1つ作る。名前は正規表現 receipt_[0-9a-f]{32} で検証する。
  • 画像ファイルは保存しない。
receipt_image_hash_registryimage_sha256 PK / table_name UNIQUE
receipt_structured_summaryreceipt_table_name UNIQUE
↓ FK（ON DELETE CASCADE）
receipt_structured_item明細
receipt_<32hex>行番号・文字列（レシートごと）
monster_cardreceipt_table_name UNIQUE
↓
monster_roomcode UNIQUE
monster_play1ルーム2行（FK CASCADE）
monster_battleUNIQUE(room, round)

monster_card.receipt_table_name は論理的に receipt_<32hex> を指す（外部キー制約なし）。

2. receipt_image_hash_registry

列型制約内容
image_sha256VARCHAR(64)PK解析済み／保存済みの画像ハッシュ
table_nameVARCHAR(64)UNIQUE（NULL可）保存後に設定。解析のみのときはNULL
created_atTIMESTAMPTZNOT NULL

3. receipt_（32桁の16進数）

列型制約内容
idBIGINTPK、IDENTITY
line_noINTEGERNOT NULL行番号（1始まり）
textTEXTNOT NULL行の文字列（個人情報は「（非表示）」済み）
created_atTIMESTAMPTZNOT NULL

4. receipt_structured_summary

列型内容
receipt_table_nameVARCHAR(64) UNIQUE対応するレシートテーブル名
image_sha256VARCHAR(64) UNIQUE画像ハッシュ
store_name / branch_nameVARCHAR(255)店名／支店
store_categoryVARCHAR(50)スーパー・コンビニ・ドラッグストア・飲食店・その他
purchased_at / total_amountTIMESTAMP / BIGINT購入日時／合計
payment_method / receipt_numberVARCHAR(100)支払方法／レシート番号

5. receipt_structured_item

列型内容
receipt_table_nameVARCHAR(64) FKsummaryへの外部キー（ON DELETE CASCADE）
item_noINTEGER明細番号。(table, item_no) で一意
item_name / categoryTEXT / VARCHAR(50)品名／食料品・日用品・飲食・交通・移動・その他
quantity / unit_price / amountNUMERIC(12,3) / BIGINT数量・単価・金額

6. monster_card / monster_room / monster_play / monster_battle

テーブル主な列備考
monster_cardreceipt_table_name、image_sha256 UNIQUE、status（DRAFT／ACTIVE）、name、element、rarity、hp、atk、defense、spd、luck、power、skill_name、skill_power、lucky、flavor、svg、algorithm_version下書きは receipt_table_name がNULL
monster_roomcode（UNIQUE）、status（WAITING／SELECTING／BATTLE／CLOSED）、mode、round_no、p1/p2のトークンハッシュ、wait_deadline、expires_at席トークンはハッシュのみ保存
monster_playroom_id（FK）、seat（P1/P2）、field_json、hand_json、flipped_json、selected_card_json、confirmedUNIQUE(room_id, seat)
monster_battleroom_id（FK）、round_no、battle_seed、winner、reason、result_jsonUNIQUE(room_id, round_no)

7. CRUD

操作テーブル
解析image_hash_registry にハッシュを予約。monster_card に下書き（DRAFT）
保存receipt_<hex>・summary・item を作成／挿入。registry にテーブル名を設定。カードをACTIVEへ
削除receipt_<hex> を削除。summary（item はCASCADE）・registry・card を削除
対戦monster_room・play・battle を作成／更新。ルームは期限切れ後に掃除

8. データ設計上の注意

  • テーブル名はSQLに文字列連結するため、固定パターン以外は拒否する。
  • ルームの掃除は5分ごと、下書きカードの掃除は10分ごと（24時間超を破棄）。
  • レシートの自動削除はしない。
