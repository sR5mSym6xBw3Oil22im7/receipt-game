1. データベース概要

項目内容
DBMSPostgreSQL（本番 Render 18、ローカル Docker postgres:16-alpine）、テストは H2（PostgreSQL互換）
データベース名receipt_db（既定）
スキーマpublic
テーブル作成アプリが実行時に作成（マイグレーションツールは使わない）
テーブルreceipt_＜32桁＞（レシートごと）、receipt_image_hash_registry、receipt_structured_summary、receipt_structured_item、monster_card、monster_room、monster_play、monster_battle

2. receipt_image_hash_registry

列型制約説明
image_sha256VARCHAR(64)PK画像のSHA-256（小文字16進）
table_nameVARCHAR(64)UNIQUE、NULL可保存済みならレシートのテーブル名。解析で予約しただけならNULL
created_atTIMESTAMPTZNOT NULL DEFAULT CURRENT_TIMESTAMP登録日時

3. receipt_（32桁の16進数）

列型制約説明
idBIGINTPK（IDENTITY）連番
line_noINTEGERNOT NULL1から始まる行番号
textTEXTNOT NULL行の文字列（個人情報を置換済み）
created_atTIMESTAMPTZNOT NULL DEFAULT CURRENT_TIMESTAMP登録日時（一覧の登録日時はこの最大値）

4. receipt_structured_summary

列型制約説明
idBIGINTPK（IDENTITY）連番（古い順の並びに使う）
receipt_table_nameVARCHAR(64)NOT NULL UNIQUEレシートのテーブル名
image_sha256VARCHAR(64)NOT NULL UNIQUE画像のSHA-256
store_name / branch_nameVARCHAR(255)店舗名・支店名
store_categoryVARCHAR(50)スーパー／コンビニ／ドラッグストア／飲食店／その他
purchased_atTIMESTAMP購入日時（2000年〜明日の範囲外はNULL）
total_amountBIGINT合計金額
payment_method / receipt_numberVARCHAR(100)支払方法・レシート番号
created_atTIMESTAMPTZNOT NULL DEFAULT登録日時

5. receipt_structured_item

列型制約説明
idBIGINTPK（IDENTITY）連番
receipt_table_nameVARCHAR(64)NOT NULL、FK → summary(receipt_table_name) ON DELETE CASCADEレシートのテーブル名
item_noINTEGERNOT NULL、UNIQUE(receipt_table_name, item_no)1から始まる商品番号（名前が空の商品は登録しない）
item_nameTEXTNOT NULL商品名
categoryVARCHAR(50)NOT NULL食料品／日用品／飲食／交通・移動／その他
quantityNUMERIC(12,3)数量
unit_price / amountBIGINT単価・金額
created_atTIMESTAMPTZNOT NULL DEFAULT登録日時

6. monster_card

列型制約説明
idBIGINTPK（IDENTITY）カードID
receipt_table_nameVARCHAR(64)UNIQUE元レシート（下書き・画像カードはNULL）
image_sha256VARCHAR(64)NOT NULL UNIQUE画像のSHA-256（応答には出さない）
statusVARCHAR(16)NOT NULLDRAFT／ACTIVE
sourceVARCHAR(16)NOT NULLANALYZE／PLAYER1／PLAYER2
name, skill_nameVARCHAR(64)NOT NULL名前・必殺技名
element, rarityVARCHAR(8)NOT NULL属性・レア度
hp, atk, defense, spd, luck, powerINTEGERNOT NULL能力値
skill_powerDOUBLE PRECISIONNOT NULL必殺技の倍率
luckyBOOLEANNOT NULLラッキー
flavorVARCHAR(255)説明文
store_categoryVARCHAR(50)店舗カテゴリー
svgTEXTNOT NULLイラスト
algorithm_versionINTEGERNOT NULL計算式の版（2）
created_at / activated_atTIMESTAMPTZ作成日時・有効化日時

レシートの行テキスト・表示内容は持たない。レシートとの連動は削除処理で行う（receipt_structured_summary への外部キーは張らない）。

7. monster_room・monster_play・monster_battle

テーブル主な列説明
monster_roomid, code VARCHAR(6) UNIQUE, status, mode, round_no, p1_token_hash, p2_token_hash, p1_seen_at, p2_seen_at, wait_deadline, expires_at, cpu_reason, notice, closed_by, created_atルーム。トークンはハッシュのみ
monster_playid, room_id（FK CASCADE）, seat（P1／P2、UNIQUE(room_id, seat)）, field_json, hand_json, flipped_json, image_card_id, image_receipt_json, selected_card_json, confirmed席ごとのプレイ状態。配ったレシートの表示内容はプレイ中だけの一時コピー
monster_battleid, room_id（FK CASCADE）, round_no（UNIQUE(room_id, round_no)）, battle_seed, winner, reason, result_json, created_atラウンドごとの対戦結果

保存U（テーブル名）C（CREATE TABLE・INSERT）CC／U（有効化）—

削除DD（DROP TABLE）DD—

9. データ設計上の注意

  • 画像ファイルそのものは保存しない。
  • レシートごとにテーブルを作るため、テーブル名は必ず ReceiptTableName.isSafe で検証してからSQLに埋め込む。
  • receipt_structured_item の外部キーは、作成時に孤立した行を消してから追加する（既存データとの互換）。
  • 金額は ±1,000,000,000、数量は NUMERIC(12,3) に収まる範囲に制限する。PostgreSQLのTEXTはNUL文字を保存できないため、NULを拒否する。
  • monster_play の JSON 列は Gson で読み書きする。
