1. 運用体制と役割

役割は 07。個人開発のため運用時間・当番は定めていません。

2. 日常運用

頻度作業確認先
毎日（または適宜）ヘルス確認/api/health
毎日エラーログ確認（5xx、Unexpected error、Database access failed）log/backend.log（Renderはダッシュボードのログ）
随時Gemini利用状況（429、GEMINI_DAILY_LIMIT）の確認ログ、Google側のコンソール
随時管理者によるレシートの解析・保存・削除54
月次月次運用報告書の作成49

3. 起動・停止・再起動

停止・再起動の前に、実際に何で動いているかを確認する（docker ps、ps、/proc/<pid>/cgroup）。systemdだと決めつけない。
環境手順
Render本番ダッシュボードから再デプロイ/再起動。起動後に /api/health を確認
ローカルDBDockerコンテナ receipt-game-db（ポート55432→5432）。再起動は docker restart receipt-game-db。ホストの postgresql.service は無関係
ローカルバックエンドcd reBack && mvn spring-boot:run -Dspring-boot.run.profiles=local
ローカルフロントnode reFront/server.mjs（5051固定）

4. 自動で行われる処理

処理周期/契機内容
ルーム掃除5分ごと（起動1分後から）期限切れ・放置ルームの整理
下書きカード掃除10分ごと（起動1分後から）24時間を超えた下書きを破棄
カードのバックフィル起動時（MONSTER_BACKFILL_ON_STARTUP）カードのない保存済みレシートへカード生成。レシートの自動削除はしない
フォルダ一括取込app.batch-import.dir 設定時の起動時のみ画像を1件ずつ解析・保存

5. 管理者の運用ルール

  • 保存前に必ず解析結果を確認する（個人情報の取り残しがないか）。
  • 画像は保存されないため、再解析が必要なら元画像を管理者側で保管する。
  • 削除すると、そのレシートのカードも削除される（対戦中のルームでは CARD_REMOVED となる場合がある）。
