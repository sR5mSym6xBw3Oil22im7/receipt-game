34. 要確認事項・検討課題事項

1. 目的

認可、入力検証、保存・削除、対戦の進行と計算、個人情報の置換、フロントの整合が仕様どおりに動くことを、自動テストで継続的に確認する。

2. テスト範囲

区分対象手段
単体ログイン試行制限、画像検査、Geminiキー選択、対戦エンジン、個人情報置換、SVG検証、テーブル名JUnit 5
結合認証・認可・CSRF、解析・保存API、入力検証、ヘッダー、直接アクセス転送、ルーム進行Spring Boot Test（MockMvc）＋H2
フロント管理画面JS／HTMLの整合、テーマ、演出、直接アクセス転送、server.mjs の拒否動作node:test（スモークテスト）
手動確認実ブラウザーでの操作、実Geminiでの解析第25章 手動確認、第34章

3. テスト環境

項目内容
OSLinux
JDK / Maven21 / 3.9.12
Node.jsv24.21.0
DBH2（インメモリ）。PostgreSQL実機は使わない
Geminiテストでは呼ばない設定（application-test.yml）

4. 開始・終了条件

  • 開始：mvn と node が使え、5051番ポートで別のプロセスが動いていない。
  • 終了：JUnit・node:test のすべてが成功し、失敗・エラー・スキップが0件。

5. テストコード構成

reBack/src/test/java/com/example/receipt/
  config/      GeminiApiKeysTest
  controller/  Authentication / ReceiptApiAuthorization / ReceiptController / Validation /
               Hardening / DirectAccessRedirect / EicarUpload の各IntegrationTest
  monster/     MonsterRoomIntegrationTest、engine/（Parity・SvgValidator・PersonalInfoSanitizer）
  repository/  ReceiptTableName / ReceiptTableRepository
  service/     GeminiApiKeyPolicy / GeminiReceiptAnalyzer / LoginAttemptLimiter / ReceiptUploadValidator
reFront/test/smoke.test.mjs

6. 不具合管理

不具合は発見した時点で原因を特定して修正し、再テストで全件成功を確認する。修正内容はコミット履歴に残す。残っている懸念は第34章に記載する。
