1. ルール概要

  • 2人（P1/P2）が1枚ずつモンスターカードを選び、自動戦闘で勝敗を決める。
  • カードは保存済みレシートから生成される。同じレシート画像からは常に同じ名前・能力値のカードができる。
  • 手札は最大3枚（HAND_LIMIT）、場のレシートは最大9枚（FIELD_SIZE）。
  • 有効なカードが10枚以上あるときだけ「シャッフル」が使える（手札が空で未決定のときのみ）。
  • レシートが0件でも、画像から作ったカードで対戦できる。

2. カードの構成

項目内容
属性炎／土／風／雷／無。明細カテゴリー別の金額合計が最大のものから決定：飲食→炎、食料品→土、日用品→風、交通・移動→雷、その他/なし→無
能力値HP（200〜700）、ATK（40〜140）、DEF（30〜110）、SPD（40〜100）、LUCK（5〜25）。ボーナス前の範囲
POWERfloor(HP/5 + ATK + DEF + SPD/2 + LUCK×2)
レア度N（274以下）／R（275以上）／SR（315以上）／SSR（345以上）
技技名と倍率（1.5〜2.0）。属性ごとに3種から決定
ラッキー合計がゾロ目（3桁以上）または末尾777／購入時刻の時と分が同じ／日付が7のつく日 のいずれか
イラストSVG。Gemini作成（検証通過時）、または代替イラスト。作成時刻で変化

3. 能力値の計算（アルゴリズム版数2）

各要素はすべて0〜1に正規化する。金額の影響はどの能力値でも25%以下。

要素定義
fA 合計金額min(合計, 30000)/30000（負は0）
fM 最高額min(最大明細額, 10000)/10000
fC 文字数min(行テキストの空白除く文字数, 600)/600
fN 品数min(明細数, 20)/20
fT 時刻|購入時−12|/12（時刻なしは12時扱い）
fW 日付(日−1)/30×0.7＋週末0.3（日時なしは0.5）
r(k)((種 >>> 5k) & 255)/255。種は画像SHA-256先頭8桁(32bit)
HP  = 200 + floor(500 × (0.25fA + 0.30fC + 0.15fN + 0.15fW + 0.15r0))
ATK =  40 + floor(100 × (0.25fM + 0.25fC + 0.15fT + 0.15fW + 0.20r1))
DEF =  30 + floor( 80 × (0.15fA + 0.30fN + 0.20fC + 0.15fW + 0.20r2))
SPD =  40 + floor( 60 × (0.35fT + 0.20fW + 0.15fC + 0.10fN + 0.20r3))
LUCK =  5 + floor( 20 × (0.50r4 + 0.25fW + 0.25fC)))
店種ボーナス効果
スーパーHP ×1.1（切り捨て）
コンビニSPD ×1.1
ドラッグストアDEF ×1.1
飲食店ATK ×1.1
その他LUCK +3
ラッキーATK・DEF ×1.1、LUCK +10

4. 戦闘ルール

  • 先攻はSPDが高い方。同値なら対戦シードの偶奇で決める。
  • 最大20ラウンド。各ラウンドで両者が1回ずつ行動する。自分の3回目ごとの行動は「技」（倍率 = 技倍率）、それ以外は通常攻撃。
  • ダメージ = max(1, round( max(1, ATK×倍率 − DEF×0.5) × (0.9〜1.1の乱数) × 属性倍率 × (会心なら1.5) ))。
  • 会心率 = LUCK％。属性相性は 炎→風→土→雷→炎 が有利（×1.25）、逆は不利（×0.8）。
  • HPが0になれば即KO勝ち。20ラウンドで決着しなければ判定：HP残存率→POWER→同じなら引き分け（DRAW）。
同じ battleSeed と同じ2枚のカードからは必ず同じ結果になる（MonsterBattleEngine、デモ画面の engine.js と一致をテストで検査）。
