2. 解析シーケンス

  1. app.js → POST /api/receipts/analyze（multipart、X-XSRF-TOKEN、210秒で打ち切り）
  2. SecurityConfig：ROLE_ADMIN と CSRF を確認
  3. ReceiptService.analyze → ReceiptUploadValidator.validate → sha256
  4. GeminiReceiptAnalyzer.analyze（ANALYZE → DEFAULT）→ request（1回目）→ 必要なら回転して request（2回目）→ toStructuredData
  5. ReceiptTableRepository.reserveImageHash（登録済みなら409、予約済みなら再解析を許す）
  6. MonsterCardService.prepareDraftAsync（別スレッド：除去 → generate → insertDraft）
  7. 200 {lines, sha256, structuredData}

3. 保存シーケンス

  1. app.js → POST /api/receipts/save（JSON、30秒で打ち切り）。未保存の結果を1件ずつ順に送る
  2. Bean Validation（@Valid ReceiptSaveRequest）
  3. ReceiptService.store：空の確認 → sha256 の正規化 → sanitizeForSave（失敗は422）
  4. prepareCardForSave（トランザクションの外）：generate → MONSTER／DEFAULT で generateParameters → applyParameters → illustrate → withSvg
  5. トランザクション：createReceiptTableAndInsert（条件付きUPDATE、CREATE TABLE、batchUpdate）→ saveStructuredData → activate（下書きを上書き、または新規）
  6. 200 {tableName, lineCount, lines, sha256}

4. カード生成の計算（アルゴリズム版数 2）

項目計算
種画像ハッシュの先頭8桁（32ビット）。r(k) = (種 >>> 5k の下位8ビット) / 255
要素fA = 合計(0〜30000)/30000、fM = 最高額(〜10000)/10000、fC = 文字数(〜600)/600、fN = 品数(〜20)/20、fT = |時−12|/12、fW = (日−1)/30×0.7 ＋ 週末0.3（日時なしは0.5）。合計がなければ商品の金額の和
HP200 ＋ ⌊500 × (0.25fA ＋ 0.30fC ＋ 0.15fN ＋ 0.15fW ＋ 0.15r0)⌋
ATK40 ＋ ⌊100 × (0.25fM ＋ 0.25fC ＋ 0.15fT ＋ 0.15fW ＋ 0.20r1)⌋
DEF30 ＋ ⌊80 × (0.15fA ＋ 0.30fN ＋ 0.20fC ＋ 0.15fW ＋ 0.20r2)⌋
SPD40 ＋ ⌊60 × (0.35fT ＋ 0.20fW ＋ 0.15fC ＋ 0.10fN ＋ 0.20r3)⌋
LUCK5 ＋ ⌊20 × (0.50r4 ＋ 0.25fW ＋ 0.25fC)⌋
属性商品カテゴリーごとの金額の和が最大のもの：飲食→炎、食料品→土、日用品→風、交通・移動→雷、それ以外・商品なし→無
店舗ボーナススーパー HP×1.1、コンビニ SPD×1.1、ドラッグストア DEF×1.1、飲食店 ATK×1.1、その他 LUCK＋3（×1.1 は ⌊×11/10⌋）
ラッキー合計が111以上のゾロ目、または下3桁が777／購入時刻の時と分が同じ／日付が7・17・27日 → ATK×1.1、DEF×1.1、LUCK＋10
POWER⌊HP/5 ＋ ATK ＋ DEF ＋ SPD/2 ＋ LUCK×2⌋
レア度POWER 345以上 SSR、315以上 SR、275以上 R、それ未満 N
必殺技倍率 = 1.5 ＋ 0.5 × (0.2fM ＋ 0.4fC ＋ 0.4r5)（小数2桁）。技名は属性ごとの3種から種で選ぶ
名前属性ごとの接頭辞4種 × 接尾辞6種（ン・ドラ・モン・ゴン・ラス・ビー）から種で選ぶ
説明文「（店舗カテゴリー）のレシートから生まれた（属性）の魔物。n品の力を宿している。」
代替イラスト種に作成時刻（yyyyMMddHHmmss）を混ぜた乱数で、属性の体形・色に、目1〜3・角0〜3・牙・ほほ紅を組み合わせる

生成AIのパラメータを使う場合も、店舗ボーナス・ラッキー・POWER・レア度はこの計算で決める（「AIレシート解析機能仕様書」5.2）。

5. 対戦の計算

項目計算
乱数battleSeed（32ビット）を種にした mulberry32
先攻SPD が高い側。同じなら battleSeed が偶数で P1、奇数で P2
進行1ラウンドに先攻・後攻が1回ずつ行動、最大20ラウンド
必殺技各自の3回目・6回目…の行動（倍率 skillPower）。それ以外は「通常攻撃」（倍率1）
ダメージmax(1, round( max(1, ATK×倍率 − 相手DEF×0.5) × (0.9＋0.2×乱数) × 属性倍率 × 会心 ))
属性倍率炎→風→土→雷→炎 の向きで有利 1.25、逆は 0.8、それ以外（無を含む）1
会心乱数 < LUCK/100 で 1.5倍
勝敗HPが0になった側の負け（KO）。20ラウンドで決まらなければ JUDGE：残りHPの割合が高い方、同じなら POWER が高い方、それも同じなら DRAW

6. ルームの進行

状態入る条件主な処理
WAITINGルーム作成P1の席を発行。待機期限 = 作成＋90秒
SELECTINGP2の参加、または待機期限の経過（mode=CPU）配布：人対人は P1 に min(9, ⌈n/2⌉) 枚、P2 にその次から最大9枚。CPU は CPU に1枚、P1 に最大9枚。ラウンド番号を1増やす
BATTLE両者が決定battleSeed を乱数で決めて計算し、monster_battle に保存
SELECTING（再戦）BATTLE 中に rematch（同じラウンド番号を指定）対戦結果を消して配り直す
CLOSEDどちらかが leaveプレイ用のコピーを消し、10分後に削除。相手には「相手がルームを閉じました。」
  • シャッフル：有効なカードが10枚以上、手札0枚、未決定のときだけ。相手の配布・手札・画像カードと自分の画像カードを除いて最大9枚を配り直す。
  • コンピュータ：P1 が決定すると別スレッドで、1〜3枚（乱数）を手札にする（配られた枚数が足りなければ未配布のカードから引く）。PLAYER2 の1日の上限内なら Gemini で選ぶ。レシートが0件のときは、DBに保存しないその場限りのカードで戦う。
  • 無応答：相手の最終アクセスが60秒より前なら opponentUnresponsive=true（人対人のみ）。

8. エラー処理

  • 業務エラーは ReceiptException（status, code, message）。ApiExceptionHandler が ErrorResponse {code, message, timestamp} に変換する。
  • Bean Validation は最初の項目のエラーだけを「入力値が正しくありません（項目）：理由」として返す。
  • DataIntegrityViolationException は422、その他の DataAccessException は503、想定外の例外は500（ログに原因）。
  • 別スレッドの処理の失敗は、例外名だけをログに残して応答には影響させない。
  • 生成AIの失敗は Optional.empty() として扱い、呼び出し側で代わりの値を使う。
