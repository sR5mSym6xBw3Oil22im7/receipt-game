3. 保存シーケンス

  1. lines が空なら400、sha256 が64桁16進でなければ400。
  2. PersonalInfoSanitizer で置換。失敗なら422（カードも作らない）。
  3. トランザクション外でカードを準備（MONSTER → DEFAULT → 計算式）。
  4. トランザクション内でテーブル作成・行挿入・構造化データ保存・カード有効化を一括コミット。

4. ルーム進行（MonsterRoomService）

処理要点
排他各操作で SELECT … FOR UPDATE（ルーム単位）により直列化
席の認可トークンのSHA-256と照合。ルームなし・席なしはどちらも403 SEAT_REQUIRED
配布対人：有効カードをシャッフルし、P1／P2へ最大9枚ずつ。CPU：CPUに1枚、プレイヤーに最大9枚

画像カード状態確認 → Gemini → 登録。既存の有効カードがあれば再利用。1体のみ
掃除ルーム5分ごと、下書きカード10分ごと

5. 戦闘ルール

  • 先攻はSPDが高い方。同値なら対戦シードの偶奇。
  • 最大20ラウンド。自分の3回目ごとの行動は技（倍率1.5〜2.0）、他は通常攻撃。
  • ダメージ = max(1, round(max(1, ATK×倍率 − DEF×0.5) × 乱数(0.9〜1.1) × 属性倍率 × 会心))。会心率はLUCK％、会心は×1.5。
  • 属性相性：炎→風→土→雷→炎が有利（×1.25）、逆は不利（×0.8）。
  • HPが0でKO勝ち。20ラウンドで決着しなければ、HP残存率→POWERの順で判定、同じなら引き分け。

7. フロントエンド構成

第13章のとおり。対戦画面は1ページ内で5ビューを切り替え、待機・選択中は1.5秒ごとに状態を取得する。

8. エラー処理

業務エラーは ReceiptException(status, code, message)。予期しない例外は INTERNAL_ERROR（詳細はログのみ）。一覧は第20章。
