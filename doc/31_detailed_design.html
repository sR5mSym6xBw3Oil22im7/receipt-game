1. バックエンド構成

バックエンドは com.example.receipt パッケージ配下に、責務ごとのクラスを配置しています。

領域主要クラス・メソッド責務
認可SecurityConfig.securityFilterChainCSRF対象の判定、URL単位の認可、未認証時の応答（/admin/ はログイン画面へリダイレクト、それ以外は401）、権限なしは403。
認証AuthController.csrf / session / loginCSRFトークン発行、ログイン状態、ログイン処理。
ログイン制限LoginAttemptLimiter.tryBegin、Attempt.succeeded / failed / close照合前の試行枠確保、結果の記録、ロック。
解析ReceiptService.analyze、GeminiReceiptAnalyzer.analyze検証、SHA-256計算、Gemini呼び出し、応答の正規化、台帳記録。
Geminiエラー分類GeminiReceiptAnalyzer.mapApiException / classifyUnexpectedGeminiFailureGeminiの失敗を利用上限・キー拒否・その他に分類。
保存ReceiptService.store、ReceiptTableRepository.createReceiptTableAndInsert / saveStructuredData台帳の確定、テーブル作成、行・構造化データの登録。
参照・削除ReceiptTableRepository.findAllReceiptTables / findReceipt / deleteReceipt一覧、詳細、削除。
例外ApiExceptionHandler例外をHTTPステータスとエラーJSONに変換。

2. 解析シーケンス

画像選択ZIPは展開
→
CSRF取得GET /api/auth/csrf
→
解析要求POST /api/receipts/analyze
→
GeminiJSONスキーマ指定
→
台帳記録・応答結果を表示

解析時の要点

  • 画像は1枚ずつ順に送信する。いずれかで失敗すると以降の画像は送らず、保存ボタンも表示しない。
  • 台帳の確認・記録はGemini解析の後に行う。保存済みなら409、未保存の記録が既にあれば再解析を許可する。
  • lines は null・空白行を除き、前後の空白を除去して先頭1,000行までとする。

3. 保存シーケンス

保存ボタン未保存の結果ごと
→
保存要求POST /api/receipts/save
→
台帳を確定UPDATE … table_name IS NULL
→
テーブル作成・登録1トランザクション
→
画面初期化全件成功時

保存時の要点

  • 台帳の更新件数が0件なら409（DUPLICATE_RECEIPT_IMAGE）とする。
  • 構造化データがない場合は、店舗カテゴリ「その他」の要約だけを登録する。商品名が空の商品は登録せず、商品番号は1から振り直す。
  • 途中で失敗した場合、画面は保存済みの結果を保持し、未保存の結果だけを再送できる。

6. エラー処理

  • 業務エラーは ReceiptException（HTTPステータス、コード、メッセージ）として投げ、ApiExceptionHandler が code・message・timestamp のJSONを返す。
  • IOException は400、DataAccessException は503、その他の例外は500の固定メッセージとする。
  • 画面は、APIキーに関するコードの場合にAPIキー欄へフォーカスし、401・403は再ログイン・再読み込みの案内に置き換える。
  • 画面の通信は AbortController で中断し、中断時はバックエンドから応答がない旨を表示する。
