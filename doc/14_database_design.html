1. 方針

  • テーブルはアプリが実行時に作成する（マイグレーションツールなし。CREATE TABLE IF NOT EXISTS）。
  • レシートごとに receipt_ + 32桁16進数のテーブルを1つ作る（ReceiptTableName が正規表現 receipt_[0-9a-f]{32} で検証）。
  • 画像ファイルは保存しない。

2. ER図（論理）

receipt_image_hash_registryimage_sha256 PK / table_name UNIQUE
receipt_structured_summaryreceipt_table_name UNIQUE / image_sha256 UNIQUE
↓
receipt_structured_itemFK→summary(receipt_table_name) ON DELETE CASCADE
receipt_<32hex>（レシートごと）line_no / text
↓
monster_cardreceipt_table_name UNIQUE / image_sha256 UNIQUE
↓
monster_roomcode UNIQUE
monster_play（1ルーム2行）FK→room CASCADE
monster_battleFK→room CASCADE / UNIQUE(room, round)

monster_card.receipt_table_name は論理的に receipt_<32hex> を指す（外部キー制約なし）。

3. receipt_<32hex>（レシートごと）

列型制約内容

line_noINTEGERNOT NULL行番号（1始まり）
textTEXTNOT NULL行文字列（個人情報は「（非表示）」済み）
created_atTIMESTAMPTZNOT NULL DEFAULT CURRENT_TIMESTAMP

9. データ量・保持

保持期間・削除方針は 51 個人情報取扱い資料 と 47 バックアップ・メンテナンス。レシートの自動削除はしない（管理者の手動削除のみ）。
